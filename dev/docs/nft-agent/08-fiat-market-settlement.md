# 天枢「角色资产化」法币市场结算模型（C 方案 v1.3）

> 版本：v1.3（2026-08-27）
> 定位：替代「可流通积分/代币」方案的可落地合规结算模型。保留用户全部商业诉求（可流动市场、平台抽成、创作者再投入），把结算媒介从「代币」换成「法币/法币余额」，从而同时规避国内非法金融活动红线与海外 SEC 证券定性。
> v1.3 更新（老板已确认参数）：①销量阶梯抽成（前3个13%/4-6个10%/7-10个8%/10+个5%）②提现门槛 ¥20 ③无赠与、支持免费上架 ④资产生成费 = 成本+20% ⑤天枢 API token = 上游成本+5% ⑥API 无免费额度 ⑦每个账号资产生成首次免费一次。
> 法律边界声明：本文为产品/结算架构设计，不构成法律意见；上线前须由具备资质的律师事务所分别出具国内与海外（美国/欧盟）法律意见。

## 〇、单一钱包计价架构（v1.2 更新）

```
                  ┌─────────────────────────────────────────────┐
                  │           天枢平台（单一钱包）                │
                  │                                             │
  ┌─────────┐     │  · 钱包 = 法币余额（人民币/美元，见 2.1 充值） │
  │ 天枢 API │◄────┤  · 调用天枢 API（对话/工具/资产生成）→ 钱包扣费 │
  │(平台服务)│     │  · 计费：按 token/调用用量，资产生成另加 20-50%│
  └─────────┘     │                                             │
                  │  · 用户自带外部 API key（OpenAI 等）→ 不经钱包 │
  ┌─────────┐     │    BYOK 直连外部供应商，平台不碰钱、不代扣      │
  │ 外部 API │◄────┤                                             │
  │(用户自带key)   │  · 硬规则：资产生成必须钱包现金（防套利/合规）  │
  └─────────┘     └─────────────────────────────────────────────┘
```

### 为什么「资产生成必须用钱包现金」？（三层理由，v1.2 保留）

| 理由 | 说明 |
|---|---|
| **1. 合规闭环** | 能进入「可交易市场」的资产，其生成成本必须用法币结算——避免任何人用外部低价通道批量铸造资产再入市，形成脱离监管的「类代币经济」 |
| **2. 防套利** | 若允许用外部 key 生成资产，会创造「低价 token → 高价卖出」的套利空间，且引入不受平台控制的成本结构 |
| **3. 成本可控** | 平台对资产生成的 token 成本有确定性（自营采购+加价），现金流可预测 |

### 单一钱包的计费规则（v1.2 更新）

| 场景 | 计费来源 | 说明 |
|---|---|---|
| 调用天枢 API（日常对话/工具/Agent 运行） | **钱包扣费** | 按 token/调用用量计费，类似 opencode zen |
| 开发者用天枢 API 集成 | **钱包扣费** | 按用量计费 |
| **创建/铸造角色资产（皮肤/人格/能力/记忆）** | **必须钱包现金** | 硬规则：外部 key 不能铸造可交易资产 |
| 资产生成过程中的推理消耗 | 钱包扣费 | 法币计价（成本+20% 加价） |
| 市场上购买他人资产 | 钱包现金 | 担保交易 |
| 用户自带外部 key 调用模型（BYOK，全用户开放） | **不经钱包** | 可接任意厂商 OpenAI 兼容 API（含 opencode go/zen），用户与供应商直接结算 |
| 提现 | 钱包 → 银行卡 | 实名+税务处理 |

**规则：只有一个钱包。调用天枢 API 就扣这个钱包；自带外部 key 就不经过钱包（用户与外部供应商直接结算，支持任意 OpenAI 兼容厂商，包括 opencode go/zen）；但「铸造可交易资产」这一件事，永远只能用钱包现金。**

## 一、模型总览

### 1.1 一句话
> 平台是「数字商品交易市场」（对标 Steam 社区市场 / 闲鱼）：用户以**法币**买卖角色资产，平台提供托管担保与结算，按**销量阶梯抽取 5%–13%** 服务费；创作者收益走**法币分账**（可提现、可再消费）；生成资产消耗的 LLM token 以**法币计价的服务费**收取（仅钱包现金），不引入任何可流通代币。

### 1.2 与老板原始设想的逐项对照

| 老板原始设想 | C 方案实现 | 差异 |
|---|---|---|
| 用户充 10 积分 | 用户充值人民币/美元（法币钱包余额） | 「积分」→「法币余额」，无兑换环节 |
| 花 5 积分创建资产 | 花 ¥5（余额）支付创建/上架费（含 token 成本） | 同上 |
| 资产以 1 积分售给 10 人 | 资产以 ¥1 售给 10 人（平台担保交易） | 交易媒介为法币 |
| 平台抽 10% | 平台按销量阶梯抽 5%–13% 服务费（前3个13%→10+个5%） | 抽成逻辑保留，阶梯激励长期销售 |
| 创作者到手 9 积分再去生成 | 创作者到账 ¥0.9×N，可提现或余额再投入 | 收益是钱，不是代币 |
| 生成资产需要 token | **资产生成必须钱包现金**（法币计价）；日常调用走天枢 API（钱包扣费）或自带外部 key（不经钱包） | 单一钱包 + 来源校验，资产入口锁定钱包现金 |

**结论：商业模式与用户体验几乎不变，法律性质完全不同。**

## 二、交易流程（买家 / 创作者 / 平台三方）

### 2.1 充值（入金）
```
用户 ──人民币(境内)/美元(境外)──→ 持牌支付渠道(微信/支付宝/Stripe/Adyen)
                                      │
                                      ▼
                              平台法币托管账户
                                      │
                                      ▼
                          用户钱包余额（人民币/美元记账）
```
- 境内走持牌支付机构（微信支付/支付宝/银联），**平台不经手未授权资金**（或采用支付机构备付金托管）。
- 海外走 Stripe/Adyen 等，天然带 KYC/AML。

### 2.2 创作者创建资产（消耗 token）
```
创作者 ──余额扣费(法币)──→ 平台
                              │ 调用 LLM/工具生成资产（token 成本）
                              ▼
                    资产入库(manifest+文件哈希)
                              │
                              ▼
                    定价上架（法币，¥1~¥128 区间建议）
```
- 创建/上架费用 = 实际 token 成本 + 20% 加价；每个账号**首次资产生成免费一次**（平台补贴，获客激励）。
- 未售出前资产归创作者，平台仅托管文件与元数据。

### 2.3 用户间交易（担保交易，核心）
```
买家下单 ¥X ──→ 平台托管 ──→ 卖家(创作者)转移资产所有权 ──→ 买家确认收货
                              │
                              ▼
              平台结算（销量阶梯抽成）：
                累计销量 1–3 份   → 平台 ¥X×13%，创作者 ¥X×87%
                累计销量 4–6 份   → 平台 ¥X×10%，创作者 ¥X×90%
                累计销量 7–10 份  → 平台 ¥X×8%， 创作者 ¥X×92%
                累计销量 10+ 份   → 平台 ¥X×5%， 创作者 ¥X×95%
```
- **担保交易**：买家付款后资金冻结在平台托管账户，资产所有权转移后解冻。对标 Steam 市场/闲鱼流程。
- **销量阶梯抽成**：按该资产**累计售出份数**计阶梯，鼓励创作者持续打磨与长期销售（而非一次性高价）。
- 支持「一次性售卖 N 份」（限量数字商品，同一资产可授权多份——用「许可份数」而非「所有权分割」，规避份额化）。
- **免费上架**：创作者可把资产定价为 ¥0（免费领取），平台不收抽成，用于引流/社区共建。
- 明确展示抽成率与当前所在阶梯，写入用户协议。

### 2.4 提现（出金）
```
创作者余额 ──实名认证──→ 平台按对公/个人结算 ──→ 银行账户
```
- 境内：代扣代缴个税（劳务报酬），保留完税凭证。
- 海外：创作者需 W-8BEN/W-9 等税务表单，平台做合规报税。
- 提现最低门槛 **¥20**（$3 级），降低小额创作者结算成本。
- **结算规则（已确认 2026-08-27）**：**钱包消费即时可用**（赚到的钱可立刻再创作/再购买），**提现 T+1**（提交提现后次工作日到账）——给风控留审查窗口，防洗钱/套利/纠纷，对标支付行业惯例。

## 三、关键机制设计

### 3.1 「N 份许可」而非「份额化」（合规关键）
- 同一资产可发行 N 份**使用许可**（每份独立 manifest 记录），买家获得「个人使用+收藏」许可。
- **不做**权益拆分、不做共有人结构、不做收益权——规避国内「份额拆分交易」与海外「证券化」红线。
- 每份许可记录在资产的 `licenses[]` 数组（见 03 格式文档扩展），哈希上链可选。

### 3.2 token 成本计价（单一钱包，v1.3）
- **调用天枢 API**：从钱包按 token/调用用量扣费（类似 opencode zen 的按调用计费模式）。计费 = **上游采购成本 + 5%**；**API 无免费额度**。该消费不产出可交易资产，但费用走钱包。
- **用户自带外部 key（BYOK，全用户开放）**：可接**任意厂商的 OpenAI 兼容 API**（OpenAI、Anthropic 及 opencode go/zen 等聚合网关），直连供应商、不经平台钱包、平台不代扣——用户与供应商自行结算，天枢只做集成（提供标准 provider 抽象层）。
- **资产生成（唯一硬约束）**：只接受钱包余额（法币），按「token 成本 + **20%** 加价」计价；**每个账号首次资产生成免费一次**（平台补贴，作为获客激励）。用户感知：「生成这个角色消耗 ¥0.3」——透明、可预期。
- **绝不让 token 额度成为可转让、可交易的资产**（token 额度只在账户内消耗）。

### 3.3 抽成阶梯（销量制，v1.3 已定）
| 累计销量（份） | 平台抽成 | 创作者到手 |
|---|---|---|
| 1–3 | 13% | 87% |
| 4–6 | 10% | 90% |
| 7–10 | 8% | 92% |
| 10+ | 5% | 95% |
| 免费上架（定价 ¥0） | 0% | —（无收入） |

- 阶梯按**单个资产的累计售出份数**计，随销量下降、长期合作。
- 对标说明：首档 13% 对标 Steam 市场 13–15%；10+ 档 5% 接近平台边际成本，鼓励爆款长销。
- 企业定制（B 端）另行项目制（20%+）服务费。

### 3.4 防套利/防洗钱机制（上线必备）
- 单账号每日交易限额、实名认证门槛。
- 异常模式检测：同 IP 对敲、价格剧烈波动、批量新号互买。
- 交易冷静期（买家确认收货窗口，如 48h）减少纠纷。
- **无赠与机制**（用户间不能私下转移资产所有权，杜绝场外定价与洗钱通道）；资产仅可通过市场担保交易转让。

## 四、合规边界对照表

| 维度 | 可流通积分/代币（原方案） | 封闭积分（B） | 法币担保市场（C，本方案） |
|---|---|---|---|
| 结算媒介 | 独立代币 | 封闭积分 | 法币/法币余额 |
| 用户间交易 | ✅ 有 | ❌ 无 | ✅ 平台担保 |
| 平台抽成 | ✅ | ❌ | ✅ 销量阶梯 5–13% |
| 创作者变现 | 代币再投入 | 仅消费 | 提现/再投入 |
| 国内定性 | 🔴 非法金融活动（十部委通知） | 🟡 边界模糊 | 🟢 数字商品交易市场 |
| 海外定性 | 🔴 证券+交易所（Howey） | 🟡 需谨慎 | 🟢 商品市场，无证券特征 |
| 牌照需求 | 虚拟货币/支付牌照 | 无 | 支付走持牌渠道即可 |
| 融资尽调 | 🔴 重大风险项 | 🟡 中性 | 🟢 现金流清晰 |

### 4.1 为什么 C 方案在海外不落 Howey（对照 Stoner Cats 案）
| Stoner Cats 违规点（已核实 SEC 2023-178） | C 方案做法 | 对照 |
|---|---|---|
| 营销突出「二级市场转售」 | 平台不承诺转售；交易是担保购买许可 | ✅ 不同 |
| 引导投资者预期「升值获利」 | 商品按使用价值定价，无升值承诺 | ✅ 不同 |
| 设 2.5% 交易版税 | 无版税，抽成为平台服务费 | ✅ 不同 |
| 鼓励买卖（交易频次高） | 正常商品流通，不做投机引导 | ✅ 不同 |

### 4.2 国内十部委通知对照
- 无虚拟货币、无代币、无 ICO → 不在非法金融活动定义内 ✅
- 交易媒介为人民币 → 无变相货币风险 ✅
- 平台抽成为服务费收入 → 无「类证券化交易平台」特征 ✅

## 五、可落地性分析

### 5.1 需要新增的工程模块
| 模块 | 说明 | 优先级 |
|---|---|---|
| 钱包/余额系统 | 法币记账、充值/扣费/提现（**单一钱包**） | P0 |
| 担保交易引擎 | 订单状态机（下单→托管→转移→确认→结算） | P0 |
| 支付渠道接入 | 境内持牌支付 + 海外 Stripe/Adyen | P0 |
| 分账与税务 | 创作者分账、代扣代缴、税务表单 | P0 |
| 资产许可登记 | manifest 扩展 licenses[]，N 份许可跟踪 | P0 |
| **资产生成计费** | **钱包现金校验：非钱包支付一律拒绝创建（含外部 key）** | P0 |
| **天枢 API 计费** | **按调用/token 用量从钱包扣费** | P0 |
| **BYOK 支持** | **用户自带外部 key 直连，按 token 透传计费，无限制、不经钱包** | P1 |
| 风控/反滥用 | 限额、异常检测、冷静期 | P1 |
| 对账与审计 | 每日对账、财务审计流水 | P1 |

### 5.2 依赖与门槛
- **支付牌照**：平台自身无需支付牌照（资金走持牌渠道托管），但需合规的支付合作协议——这是上线前提。
- **税务主体**：境内需公司主体开票/代扣；海外需结算主体（Delaware C-Corp 或新加坡公司等）。
- **法律意见**：国内外各一份，覆盖「商品交易市场+担保交易+创作者分账」定性。

### 5.3 与既有产品的关系
- 资产格式（03 文档）不变，仅扩展 `licenses[]` 字段。
- 产品方案（04 文档）商业模式章节按本文修订。
- BP（07 文档）商业模式/合规章节按本文修订。
