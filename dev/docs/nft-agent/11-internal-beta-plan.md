# 天枢封闭内测计划（Client Beta v1）

> 版本：v1（2026-08-27）
> 目的：在正式发布（客户端+市场一次发布）前，用最小成本收集「需求信号」，为融资 BP 提供真实数据、用户语录与 demo 素材。
> 原则：**内测不发公开版本、不做真实支付**——验证的是「想不想拥有角色、愿不愿意为角色付费」的意愿，不是真实交易流水。所有测试用免费额度/模拟余额进行。

---

## 一、内测要验证的核心假设（写进 BP 的证据）

| # | 假设 | 内测怎么验证 | 可产出的 BP 数字 |
|---|---|---|---|
| H1 | 用户对「可拥有、可换肤的 AI 角色」有情感/购买意愿 | 角色皮肤/动画试玩 + 付费意愿问卷 | 付费意愿率（如 ≥30%） |
| H2 | 用户愿意为「角色人格/能力」付费（不只是视觉） | 展示能力包/人格差异，问「会为哪种角色付费」 | 付费点排序（视觉 vs 人格 vs 能力） |
| H3 | 用户有「自己创作角色」的意愿（创作者供给端） | 提供简易创作流程 + 意愿登记 | 创作者意向率 |
| H4 | 桌面 Agent 的日常使用成立（留存前提） | 真实使用 1-2 周，跟踪活跃 | 次日/7 日留存（哪怕小样本） |
| H5 | 「免费上架+首免生成+¥20提现」能刺激冷启动 | 问卷测试定价敏感度 | 定价接受区间 |

## 二、招募（目标 50–100 人）

### 2.1 目标人群（优先级）
1. **老板私域**：熟人、前同事、行业朋友（最容易拿到，先跑通流程）
2. **开发者/效率人群社群**：本地开发者群、效率工具爱好者、AI 工具群（与天枢「生产力 Agent」定位最契合）
3. **即梦/角色创作相关渠道**：若老板有即梦背后资本或社区资源，可作为首批尝鲜者（内容创作者对「角色/皮肤」天然敏感）
4. **二次元/角色收藏爱好者群**：验证 H1 的高意愿人群（可少量）

## 三、内测任务清单（用户要做的事）

### 3.1 任务 1：开箱体验（5-10 分钟）
- 安装客户端 → 激活一个内置角色（如小红/塔罗）→ 对话 5 轮
- 切换一次皮肤/动画（若有可切换项）→ 截图

### 3.2 任务 2：角色探索（10-15 分钟）
- 至少试用 3 个内置角色，感受人格/能力差异
- 记录：最喜欢哪个角色、为什么

### 3.3 任务 3：创作体验（可选，10 分钟）
- 用客户端（或描述方式）尝试创作一个自己的角色
- 记录：创作过程顺不顺、想创作什么样的角色

### 3.4 收尾问卷（5 分钟）
- 付费意愿（0-10 分 + 愿意为哪类付费）
- 定价敏感度（皮肤 ¥6/¥12/¥30、完整角色 ¥30/¥68/¥128 的接受度）
- 创作者意愿（会不会想卖自己的角色）
- NPS（会推荐给朋友吗）

## 四、反馈收集机制

### 4.1 收集渠道
| 渠道 | 用途 |
|---|---|
| 内测群（微信群/Telegram/Discord） | 日常反馈、问题答疑、社区氛围 |
| 问卷（腾讯问卷/Typeform/飞书问卷） | 结构化数据（付费意愿/NPS/定价） |
| 1v1 访谈（5-10 人深聊） | 拿到「用户语录」——BP 里最生动的证据 |
| 客户端埋点 | 角色使用次数、对话数、停留时长、激活/留存（见 4.3 埋点方案） |

### 4.2 收集的产出物
- **结构化数据表**：激活数、完成率、留存、付费意愿率、NPS
- **用户语录库**：5-20 条原话（「我居然会对一个 AI 秘书有占有欲」这类）
- **截图/录屏素材**：用户实际使用画面（可作 BP 配图/产品页素材）

### 4.3 埋点方案（轻量、自建优先）

**目标**：只统计使用行为（激活/角色使用/对话/留存），**不采集对话内容与个人敏感信息**。

**方案 A：自建极简接收端（推荐，1-2 天工作量）**
- 在现有后端/服务器加一个 `POST /api/telemetry` 端点：
  - 入参：`{ event, charId?, ts, anonId }`（无用户身份，匿名 ID 由客户端本地生成一次并持久化）
  - 落库：SQLite/Postgres 一张 `telemetry` 表即可
  - 看板：简单 SQL 查询或接 Grafana/Metabase（可选，前期直接查库也行）
- 客户端：在关键动作处 fire-and-forget 上报（不阻塞 UI、失败静默）：`app_launch`、`char_activate`、`char_switch`、`chat_msg`、`motion_switch`、`asset_create`、`session_end`
- 优点：数据完全在自己手里、格式自由、成本≈0；为以后正式版埋点打基础。

**方案 B：接入第三方（PostHog 等）**
- PostHog 有免费档（事件量内免费）、开源可自托管、国内可部署；事件上报一行 SDK。
- 适合不想自己写端点的场景；注意数据出境合规（用户在中国 → 优先自托管或国内节点）。

**方案 C（正式版再加，内测不做）：付费分析平台**（Amplitude/Mixpanel），等有规模再说。

**埋点回传的完整链路（A 方案示意）**
```
客户端(本地生成 anonId, 事件+时间戳)
   │  fire-and-forget HTTPS POST
   ▼
服务器 /api/telemetry  →  telemetry 表 (event, charId, ts, anonId)
   │
   ▼
老板看板：查库/简单面板 → 激活数/留存/角色热度
```

**隐私与合规（内测就要注意）**
- 只上报行为事件，**不上报对话内容、不上报用户名/邮箱**；匿名 ID 与问卷结果通过用户填的「内测编号」关联（可选）。
- 内测协议里写明「使用行为将匿名统计用于产品改进」。
- 若用户在中国境内：数据存境内服务器或自托管；海外用户同理避免把个人数据传回不必要的地方（行为事件本身敏感度低，但口径保持一致）。

## 七、合规与注意事项

1. **内测不做真实支付**：不用接支付系统，用「免费额度/模拟余额」测试；问卷问的是「意愿」不是真交易——避免内测阶段就触碰支付/虚拟商品监管。
2. **数据最小化**：只收集内测所需数据；用户隐私（对话内容）默认不收集，若收集需单独同意。
3. **协议**：内测用户签简易《内测协议》——体验数据可匿名用于产品改进与对外展示；禁止公开传播内测内容（可选）。
4. **范围控制**：这是内测不是公测，人数控制在 50-100，避免「半成品口碑扩散」。

5. **内测周期**：3-4 周是否可接受（可与主体注册并行）。
