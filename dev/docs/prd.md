## 1. 产品概述（已对齐项目现状）

**天枢（TianShu）** 是一个开源的、**本地运行的多角色 AI Agent 工作台**（GitHub: `dmql98/tianshu`）。现状事实：

- **产品定位**：面向桌面工作的多角色 AI Agent 系统——不只对话，还能读项目、调工具、执行命令、委托子 Agent、管理长期目标
- **核心能力**：角色系统（Soul/User/Memory 人格配置）、技能包（懒加载、市场「星河」）、MCP 扩展、子 Agent 委托、执行/运行策略三层防护、目标与规划（Direct / Plan-first / Goal）、事件系统（定时任务）、主题系统（浅色「天枢浅色」/深色「天枢玄夜」/图片取色自定义）
- **星宿命名体系**：内置角色以星宿命名（长庚、天璇、文曲、紫微），市场区称「星河」——天然的新国风品牌资产
- **当前分发**：仅 Windows 安装版（`TianShu-Setup-<版本>-x64.exe`，GitHub Releases + electron-updater `latest.yml`）；macOS/Linux 有构建脚本（`dist:mac:x64/arm64`、`dist:linux:x64`）但尚未正式发布
- **现有更新机制**：启动静默检查 → 提示 → 手动下载 → 重启安装（基于 GitHub Releases）

本项目为其建设**独立官网**，承载三大职责：

1. **品牌门面**：以「新国风」视觉讲清楚天枢是什么（对标 OpenClaw / Hermes 官网的信息架构，视觉走自己的宣纸+黑墨体系）
2. **分发渠道**：用户可直接从独立站下载各平台客户端（不再只依赖 GitHub Releases）
3. **更新中枢**：客户端检查更新**优先请求自有服务器**，GitHub Releases 兜底，保障国内用户更新速度与可用性

### 1.1 目标用户

| 用户群 | 诉求 |
|---|---|
| 开发者 / AI 玩家 | 快速了解产品 → 下载 → 跑起来 |
| 国内用户 | GitHub 下载慢/不稳定，需要自有 CDN 分发 |
| 潜在贡献者 | 找到 GitHub 仓库、文档、社区入口 |

### 1.2 参考对标

- **openclaw.ai**：Hero + 一键安装命令 + 多平台下载 + 用户口碑墙
- **hermes-agent.nousresearch.com**：编号式功能卡（#1~#6）、桌面端下载卡、终端安装 Tab
- 共同语言：暗色极客风、等宽字体终端块、开源徽章、"跑在你自己机器上"的信任叙事

| # | 功能 | 优先级 | 说明 |

| F7 | 快速上手三步 | P1 | 下载 → 配置模型 → 开始对话 |

### 2.2 下载与更新服务（后端，部署在自有服务器）

| # | 接口 | 优先级 | 说明 |
|---|---|---|---|
| B1 | `GET /api/v1/releases/latest?channel=stable&os=win&arch=x64` | P0 | 返回最新版本号、下载地址、SHA256、发布时间 |
| B2 | `GET /download/{os}/{arch}` | P0 | 302 跳转至安装包（自有存储/CDN），带统计 |
| B3 | `GET /api/v1/update/check` | P0 | 客户端更新检查端点（客户端传当前版本，返回是否有新版 + 增量/全量包地址） |
| B4 | GitHub Releases 同步任务 | P0 | 服务器定时拉取 GitHub Release 产物并同步到自有存储，保证两边版本一致 |
| B5 | 更新兜底逻辑（客户端侧） | P0 | 请求自有服务器超时(>5s)或失败 → 回退 GitHub Releases API；全部失败提示手动下载 |
| B6 | 签名校验 | P1 | 安装包附带 SHA256 + GPG/ed25519 签名，客户端更新前校验 |
| B7 | 下载统计面板 | P2 | 分平台/分版本下载量统计 |

**更新优先级逻辑（客户端实现）：**

```
检查更新
  ├─ 1. GET https://updates.tianshu.dev/api/v1/update/check   ← 自有服务器（优先）
  │     ├─ 成功 → 返回更新包 URL（自有 CDN 加速）
  │     └─ 超时/失败 ↓
  ├─ 2. GET https://api.github.com/repos/{org}/tianshu/releases/latest  ← GitHub（兜底）
  │     └─ 成功 → 使用 GitHub 资产地址
  └─ 3. 均失败 → 提示用户前往官网手动下载
```

## 3. 用户交互路径（User Flows）

### 流程 A：新用户下载（主路径）

```
访问官网
  → Hero 区（3 秒内理解"开源 AI 智能体平台，本地运行"）
  → 点击「下载客户端」
  → 页面平滑滚动至下载区（已自动识别并高亮其 OS 卡片）
  → 点击对应平台下载按钮
  → 浏览器开始下载（走自有服务器 B2）
  → 页尾提示"安装后打开，配置你的第一个模型服务商"
```

### 流程 B：极客一键安装

```
访问官网 → Hero 下方终端块
  → 切换 macOS/Linux 或 Windows Tab
  → 点击复制按钮（按钮变为 ✓ 已复制）
  → 粘贴到终端执行
```

### 流程 C：老客户端静默更新

```
客户端启动 → 请求自有更新接口（B3）
  → 有新版 → 弹更新提示 → 用户确认 → 从自有 CDN 下载 → 校验 SHA256 → 热更新
  → 自有服务器不可达 → 自动回退 GitHub Releases → 同上
```

### 流程 D：贡献者路径

```
官网导航栏「GitHub」→ 跳转仓库 → Star / Issue / PR
官网页脚「文档」→ 跳转 docs 站
```

## 5. 非功能性需求

- **性能**：首页 LCP < 2.5s；静态资源全部可 CDN 化；首屏无阻塞渲染
- **可用性**：下载与更新接口 SLA 目标 99.9%；GitHub 兜底链路常备
- **安全**：全站 HTTPS；安装包 SHA256 + 签名校验；更新接口只读、不收集用户隐私
- **SEO**：语义化 HTML、Open Graph 卡片、`zh-CN` lang、描述性 title/meta
- **无障碍**：WCAG AA 对比度；键盘可达；`prefers-reduced-motion` 下关闭动效
- **响应式**：移动优先；下载卡移动端纵向堆叠；触控目标 ≥44px
