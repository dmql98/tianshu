手机 → 云中继 → 多电脑 云端只转发，不存业务数据 所有服务共用一个登录 天枢 server 零改动 域名：www.tianshuapp.tech
一句话概括：手机 App 通过 www.tianshuapp.tech 上的账号中心登录，选中自己的一台电脑后，所有请求经云端 /remote 沿「电脑主动建立的 WSS 隧道」透传到本机天枢 127.0.0.1:3456——电脑常开在线，云只当中转，数据永远留在自己电脑上。

1要开发的三大块

① cloud-server（云端）

独立项目，与官网同机部署

  • /auth：注册 / 登录 / 刷新 / me / jwks（唯一账号库）
  • /remote：设备目录 + WSS 隧道 + HTTP/SSE 透传
  • 技术：Hono + ws + jose + node:sqlite，零外部基础设施

② 桌面端 cloud-tunnel

Electron main 增量（天枢 server 不改）

  • cloud-auth：/auth 登录，token 存 safeStorage
  • cloud-tunnel：WSS 连云 + 本地 HTTP 透传 + 心跳重连
  • 设置页「云远程」开关；开机自启；本地模式不变

③ 手机 App（Android APK）

Electron 不支持 Android → 用 Capacitor（WebView 壳，思路同款）

  • mobile-web（复用 web/client 组件）→ npx cap sync android → APK
  • 登录（与桌面同一账号）→ 设备列表 → 聊天
  • 壳加载 /mobile（同源无 CORS，SSE 原生可用）

2URL 布局（同域子路径，Nginx 分流）

www.tianshuapp.tech/*                官网现有内容（不动）
www.tianshuapp.tech/auth/*            统一账号中心
www.tianshuapp.tech/remote/*          远程服务
  /remote/ws                  电脑 WSS 隧道接入点
  /remote/d/<deviceId>/api/*  转发面（REST+SSE）

为什么要 www？

官网现在 tianshuapp.tech（裸域）301 → www，而 WebSocket 不跟随 301——客户端全部写死 www 避免断连。证书由官网现有 certbot 管理，只加 Nginx location，不碰证书配置。

未来演进：拆子域 account./remote.tianshuapp.tech 只是改反代，代码零改。

3里程碑与验收

M0

基建：项目骨架 + 服务器 + Nginx 分流0.5~1 天

  • 本机建 cloud-server/；服务器装 Node 24
  • 改官网 Nginx conf：443 块加 /auth/、/remote/、=/remote/ws 三段（www + 裸域都加）
✅ 验收：https://www.tianshuapp.tech/remote/health → 200；/auth/me → 401（分流生效）；官网不受影响
M1

cloud-server：统一登录 + 远程转发3~4 天

  • /auth：register / login / refresh / me / jwks；JWT access 30min + refresh 30d（可撤销）；scrypt 加盐
  • /remote：设备 CRUD、WSS 隧道（心跳 25s / 超时 70s）、REST 透传 + SSE 桥接
  • 单测 + 本机「伪电脑」端到端链路
✅ 验收：curl 经 /remote 打到本地天枢真实 API；同一 token 可同时访问 /auth/me 与 /remote/devices（统一登录互通）
M2

桌面 cloud-tunnel + 登录 UI3~5 天

  • cloud-auth（fetch /auth，token 存 safeStorage 自动续期）
  • cloud-tunnel（WSS → 本地 127.0.0.1:3456 透传，指数退避重连）
  • Electron main/preload IPC + 设置页「云远程」面板
✅ 验收：桌面登录上线 → /remote/devices 显示 online；云上 curl 调电脑真实数据；关掉中继本地照常
M3

手机 App：mobile-web + Capacitor → MVP1~2 周

  • mobile-web 复用 web/client store/api/eventBus；路由：登录 → 设备列表 → 会话 → 聊天
  • npx cap add android 出 APK；壳加载 www.tianshuapp.tech/mobile（同源）
  • 流式 markdown、中止、approval 按钮；设备离线横幅
✅ 验收（MVP 判定）：Android 真机装 APK → 登录 → 选在线电脑 → 发消息 → 逐字收到流式回复 → 中止生效；离线有明确提示
M4

端到端打磨2~3 天

  • 第二台电脑接入、路由切换不串会话
  • 断网 / 关 app / 休眠恢复 / 服务器重启全自动恢复（≤30s）
  • 错误码规范化 + 转发层防护（超时 / 并发 / body 上限 / SSE 泄漏清理）

4API 契约（/auth + /remote）

# ── 统一账号中心（所有服务共用一个登录）──
POST /auth/register    {username, password}            → {user}
POST /auth/login       {username, password}            → {access_token, refresh_token, user}
POST /auth/refresh     {refresh_token}                 → {access_token}
GET  /auth/me         (Bearer)                         → {user}
GET  /auth/jwks                                          → 公钥（未来服务验签）

# ── 远程服务（Bearer 必须 = 设备 owner）──
POST /remote/devices/register   (Bearer) {hostname, os, machine_id} → {device}
GET  /remote/devices            (Bearer)                → [{id,name,os,online,last_seen}]
PATCH|DELETE /remote/devices/:id (Bearer)
POST /remote/d/:deviceId/api/events        # 上行透传 chat-run/abort/…
GET  /remote/d/:deviceId/api/events/stream?token= # SSE 下行
GET|POST|PATCH|DELETE /remote/d/:deviceId/api/*   # 其余 REST 透传

隧道帧（WSS JSON）

电脑 → 云

register · response{id,status,…} · sse-event · heartbeat

云 → 电脑

request{id,method,path,…} · sse-subscribe · sse-close · heartbeat

登录态：access 30min + refresh 30d；两端只存 refresh 于本地安全区；401 静默 refresh 一次，失败才踢回登录。

7风险与对策

风险对策
SSE 跨隧道桥接丢帧/断流（核心体验）M1 起脚本压测；断流自动重订阅；M3 优先验收
电脑休眠/断电 → 设备离线桌面开机自启 + 引导关睡眠；离线明确提示
云服务器被攻击只开 80/443；HTTPS；登录限流；JWT_SECRET 强随机；token 可撤销
中继看到明文流量（隐私）本期信任模型明示；后续隧道 payload 加 E2EE
官网 Nginx 改动影响 cloud-server/auth、/remote location 配置进版本管理（nginx-cloud.include）
服务器归属不明（阿里云 43.161.198.188 vs "腾讯云"）已确认 43.161.198.188（README 为准）；cloud-server 与官网同机
Electron 不支持 Android手机端用 Capacitor（WebView 壳）；Electron 只用于桌面 cloud-tunnel
