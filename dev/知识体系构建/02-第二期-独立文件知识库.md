# 第二期：独立文件知识库

## 1. 本期目标

在角色记忆已经独立完成后，一次交付单独的文件知识库：

- 用户上传文件并永久保留原件。
- 异步转换成版本化 Markdown。
- 使用 Markdown 分块、FTS 和向量化。
- Agent 通过知识工具按需搜索和读取。
- 引用可回到原文件页码、Sheet、幻灯片或行号。

知识库不写入 Character Memory，也不使用 Memory 的表、状态或管理页面。

## 2. 与其他系统的边界

| 系统 | 本期处理 |
|---|---|
| Character Memory | 不修改；只与知识工具并列出现在角色 Tool Loadout |
| CodeGraph | 继续使用现有工具，不导入文件知识库 |
| Graphify | 继续使用现有图谱和查询能力，不重复建索引 |
| Skill | 可绑定知识工具，但不把文档自动变成 Skill |

允许复用通用 Job、EmbeddingProvider、VectorStore 等基础设施；不允许共用事实表或把 KnowledgeChunk 伪装成 MemoryItem。

## 3. 支持格式

首版完整支持：

- md、txt。
- html、htm。
- docx。
- 数字文本 PDF。
- csv、xlsx。
- pptx。
- 已批准的源码扩展名。

扫描 PDF 或图片 OCR 若不实现，必须明确显示 unsupported_ocr，不能产生空白知识源。

## 4. 文件生命周期

1. 校验文件名、大小、MIME、压缩容器和磁盘空间。
2. 流式写入临时文件并计算 SHA-256。
3. 原子保存不可变原件。
4. 创建 KnowledgeSource 和 KnowledgeVersion。
5. Converter 生成 normalized Markdown、source-map 和附件。
6. 校验输出后生成 Chunk。
7. 建立 FTS 并异步生成 Embedding。
8. 运行最小检索自检。
9. 原子设置 active_version 和 ready。

失败版本不能成为 active；重新转换创建新版本，不覆盖原文件、旧 Markdown 或用户修订。

## 5. 存储结构

    knowledge/
      originals/{sourceId}/{versionId}/original.ext
      normalized/{sourceId}/{versionId}/content.md
      curated/{sourceId}/{versionId}/content.md
      maps/{sourceId}/{versionId}/source-map.json
      attachments/{sourceId}/{versionId}/
      indexes/
      temp/

数据库只保存受控相对路径和 Asset ID。原文件是证据，normalized Markdown 是确定性工作副本，curated Markdown 是用户修订。

## 6. Markdown 和来源映射

- UTF-8、LF。
- 保留标题、列表、表格、代码块、链接和图片引用。
- PDF 保存 page；DOCX 保存 heading/paragraph。
- XLSX 保存 sheet/range；PPTX 保存 slide/shape。
- 文本和代码保存 startLine/endLine。
- HTML 保存 heading/domPath。

每个 Chunk 必须携带 sourceAnchor，引用展示为“文件名 + 原文件位置”。

## 7. 分块

1. 按 Markdown AST 和标题层级分割。
2. 表格、代码块和列表尽量保持原子。
3. 超长节点再按段落或句子分割。
4. 默认 500–900 tokens、重叠 80–120 tokens，配置化。
5. 保存 headingPath、tokenCount、contentSha256、相邻块和来源锚点。

Chunk ID 和引用结构从首版稳定，不能为了后加向量重新分块。

## 8. 检索

首版即通过统一 KnowledgeRetrievalService：

- FTS5/BM25 lexical 召回。
- 可配置 Embedding 向量召回。
- RRF 融合。
- 绑定、状态、版本和权限过滤。
- 去重、多样性和 token 预算裁剪。

Embedding Provider 未配置或故障时走同一接口的 lexical-only 模式，不存在未来要替换的 FTS 临时接口。

## 9. Agent 工具

- knowledge_search：按查询、来源、标签和绑定范围搜索。
- knowledge_read：按 Chunk 或 Source 有限范围读取。
- knowledge_list_sources：列出角色当前可访问的知识源。

工具结果是 Tool Message，不放入角色的固定 Memory Snapshot。角色必须通过 Knowledge Binding 才能访问知识源。

CodeGraph/Graphify 保持各自现有工具；knowledge_search 不代理、不复制它们。

## 10. 最终数据模型

本期一次建立：

- knowledge_sources
- knowledge_versions
- knowledge_chunks
- knowledge_fts
- knowledge_embedding_indexes
- knowledge_embedding_records
- knowledge_bindings
- knowledge_jobs
- knowledge_usage_logs
- knowledge_deletion_runs

FTS 和向量是可重建派生数据；KnowledgeVersion 与原件是事实层。

## 11. UI

- 文件拖拽和批量上传。
- 来源、版本、绑定、转换与索引状态。
- 原文件下载。
- normalized/curated Markdown 预览。
- 来源位置预览。
- 失败原因、警告、重试和删除。
- 检索调试器：BM25、向量、RRF、过滤和最终引用。

知识库页面与记忆中心完全分开。

## 12. 安全

- 真实 MIME 和魔数校验。
- ZIP/OOXML 限制文件数、总大小和压缩比。
- 不执行宏、脚本、公式或外链。
- 转换任务限制超时、内存和并发。
- Markdown 预览消毒。
- 外部 Embedding 默认关闭，并明确提示数据外发。

## 13. 迁移

当前知识页面无正式数据模型，因此直接建立最终结构，不创建中间表。若已有实验文件，只能通过正式上传/导入流程进入最终 KnowledgeVersion。

本期不修改 Character Memory 迁移，也不把 memory.md 导入知识库。

## 14. 验收

- 上传后同时保留不可变原件和版本化 Markdown。
- 支持格式均有正确结果或明确错误。
- 每个命中可定位原文件。
- BM25 和向量使用同一业务接口。
- Provider 故障不阻断关键词检索。
- 未绑定角色无法搜索或读取。
- 删除覆盖文件、FTS、向量、缓存和 Binding。
- CodeGraph/Graphify 没有被重复实现或导入。

## 15. 交付物

- 最终 Knowledge Schema。
- Converter、Chunker、版本和资产服务。
- FTS、Embedding 和 RRF 检索。
- 三个 Agent 知识工具。
- 独立知识库 UI 和调试器。
- 格式样本、打包、权限、删除和恢复测试。
