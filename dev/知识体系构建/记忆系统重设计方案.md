# 天枢记忆系统重设计方案（v2）

## 设计原则

1. **Snapshot 优先**：鼓励模型在每次对话产生有价值的发现时主动触发 Snapshot，而不是事后手动搬运
2. **Read 要有全局视角**：不只是"读一条记忆"，而是让模型重建对某个话题的完整认知
3. **写操作主动触发**：写操作由模型在对话中识别到值得记住的时刻时自主触发，不依赖用户指令
4. **没有永久删除**：Agent 只能归档（archive），永久删除只能用户在前端手动操作——防止误删
5. **不绑定现有的 `read/write` 工具**：这是独立的记忆系统工具，与文件系统的 read/write 完全解耦

---

## 三层操作模型

### Snapshot 层（最高优先级，强烈鼓励）

| 工具 | 用途 | 注入条件 |
|---|---|---|
| `memory_snapshot` | 当前对话产生有价值发现时，主动触发快照：把本轮对话中的关键事实/偏好/决定/结论批量写入记忆 | editable |

Snapshot 是记忆系统最重要的写入口。模型不需要手动 remember 一条条内容，而是在对话末尾/重要节点触发 Snapshot，一次性把整个对话的精华写入。

Snapshot 内部会做：
- 去重：与现有记忆比对，只保留新事实
- 压缩：超过 charLimit 时从最旧开始裁剪
- 格式化：把对话内容结构化为 `[timestamp] 类型 | 内容` 条目

### Read 层（全局重建视角）

| 工具 | 用途 | 注入条件 |
|---|---|---|
| `memory_read` | 获取某个角色/话题的完整记忆视图：支持按关键词过滤、按时间范围查询、返回结构化摘要而非原始条目 | off 时不注入 |

Memory_read 的重点不是"读原始条目"，而是**帮助模型重建上下文认知**：
- 支持 `filter` 参数（关键词过滤）
- 支持 `topic` 参数（按主题分组返回）
- 返回格式：先给摘要（重要发现/偏好/约定），再给原始条目
- 用于对话开头重建认知，或处理复杂话题时交叉参考

### Write 层（精确操作）

| 工具 | 用途 | 注入条件 |
|---|---|---|
| `memory_write` | 写入一条新记忆条目（显式 remember） | editable |
| `memory_update` | 更新一条已有记忆（按 ID 或内容子串匹配修改） | editable |
| `memory_archive` | 归档一条记忆（标记为已归档，不再出现在默认 read 视图，可恢复） | editable |

> **注意**：Agent 没有永久删除能力。归档（archive）是 agent 能执行的最大限度。
> 永久删除只能由用户在前端记忆浏览器 UI 手动操作（与知识库删除路径一致）。

## 三档模式与注入矩阵

| memoryMode | memory_read | memory_write | memory_update | memory_archive  | memory_snapshot | ## Memory prompt |
|---|---|---|---|---|---|---|---|
| **off** | ❌ | ❌ | ❌ | ❌  | ❌ | 不注入 |
| **read_only** | ✅ | ❌ | ❌  | ❌ | ❌ | 注入 + 说明 read |
| **editable**（默认） | ✅ | ✅  | ✅ | ✅ | ✅ | 注入 + 说明全部 |
| undefined（老角色兼容） | ✅ | ✅  | ✅ | ✅ | ✅ | 注入 + 说明全部 |

## 工具详细设计

### memory_snapshot
```typescript
// 参数
{
  summary?: string  // 可选摘要（模型自己总结本轮发现）
}

// 返回
{
  created: number       // 本次写入的新条目数
  total: number         // 写入后总条目数
  char_usage: number    // 当前记忆字符使用量
  char_limit: number    // 字符上限
  hint?: string         // 接近上限时给出精简建议
}
```

### memory_read
```typescript
// 参数
{
  filter?: string       // 关键词过滤（子串匹配）
  topic?: string        // 按主题分组（模糊匹配条目内容）
  limit?: number        // 最多返回条目数（默认全部）
}

// 返回（结构化摘要格式）
{
  summary: string       // 重要发现/偏好/约定的结构化摘要
  entries: Array<{
    id: string
    ts: string
    type: 'fact' | 'preference' | 'decision' | 'note'
    content: string
  }>
  total: number         // 符合条件的总条目数
}
```

### memory_write
```typescript
// 参数
{
  content: string       // 记忆内容
  type?: 'fact' | 'preference' | 'decision' | 'note'  // 条目类型（默认 note）
}

// 返回
{
  id: string            // 新条目 ID
  total: number         // 写入后总条目数
  char_usage: number
  char_limit: number
}
```

### memory_update
```typescript
// 参数
{
  id?: string           // 条目 ID（精确匹配）
  match?: string        // 内容子串匹配（fallback）
  content: string       // 新内容
}

// 返回
{
  updated: boolean
  entry?: { id, ts, content }
}
```

### memory_archive
```typescript
// 参数
{
  id?: string
  match?: string        // 内容子串匹配
}

// 返回
{
  archived: boolean
  remaining: number
}
```

### memory_delete
```typescript
// 参数
{
  id?: string
  match?: string        // 内容子串匹配（精确匹配避免误删）
}

// 返回
{
  deleted: boolean
  remaining: number
}
```

## 记忆条目 schema

```typescript
interface MemoryEntry {
  id: string              // UUID，写入时生成
  ts: string              // ISO 时间戳
  type: 'fact' | 'preference' | 'decision' | 'note'
  content: string
  archived?: boolean      // 归档标记
  source?: 'user' | 'snapshot' | 'assistant'  // 来源
}
```

**memory.md 格式（v2）**
```markdown
# 记忆

- [2026-08-31 15:04] fact | 用户喜欢用 TypeScript 写前端
- [2026-08-31 15:05] decision | 项目采用 pnpm 而不是 npm
- [2026-08-31 15:06] note | 用户对单元测试态度积极
- [2026-08-31 15:07] [archived] preference | 以前用过 Webpack，后来迁移了
```

## 记忆系统边界（Bounded Context）

记忆系统是完全独立的 bounded context，与知识库/工具/UI/删除路径完全解耦。

### 存储隔离

```
<dataDir>/
  characters/<charId>/
    character.json       ← 角色配置（含 memory.mode/charLimit 等元数据）
    memory.md            ← 记忆条目（A 档：原始记忆，逐条存储）
    knowledge/           ← 知识库（B 档：由知识系统管理，与记忆无关）
```

- **memory.md** 只存 `memory_write`/`memory_snapshot` 写入的条目
- **knowledge/** 由知识系统独立管理，记忆工具不读不写
- **character.json** 的 `memory` 字段只存配置元数据，不存条目内容

### 系统注入点

记忆在两个位置被注入上下文，但内容完全来自同一个 `memory.md`：

```
                    memory.md
                   /         \
                  /           \
    system prompt 注入         memory_read 工具读取
    (## Memory 段)            (结构化摘要)
    └─ 新会话固定前缀           └─ 按需查询（filter/topic）
       不参与 token 计算          参与当轮 token 计算
```

**两者的区别**：

| | system prompt ## Memory | memory_read 工具 |
|---|---|---|
| 注入时机 | 新会话开始 | 模型主动调用 |
| 内容格式 | 原始 memory.md 文本 | 结构化摘要 + 条目列表 |
| token 占用 | 固定计入前缀预算 | 仅当轮计入 |
| 更新频率 | 会话内不自动更新 | 每次调用实时读取 |
| 作用 | 提供基础认知背景 | 精确检索特定话题记忆 |

### 写操作触发规则

**模型应主动触发写操作的场景**（工具 description 里明确告知）：

1. **对话末尾/关键节点**：用户明确表达了偏好/决定/约定 → 触发 `memory_snapshot`
2. **对话中识别到**：用户陈述了事实、偏好、或做了一个决定 → 触发 `memory_write`
3. **纠正/更新**：发现现有记忆与当前信息矛盾 → 触发 `memory_update`

**模型不应写的场景**：
- 一次性寒暄、客套话
- 可从对话历史恢复的临时信息
- 纯技术操作细节（由文件系统/知识库管理）

### token 预算分配

```
总 token 预算
├── system prompt（含 ## Memory 段）
│   └── memory 部分：charLimit 字符 ≈ 预估 token 数
├── 对话历史（user + assistant messages）
├── 工具调用 + 结果
└── memory_read 返回（当轮临时占用）
```

**charLimit 的含义**：
- 既是 `memory.md` 的字符上限（超限自动压缩最旧条目）
- 也是 system prompt 中 `## Memory` 段的预估 token 预算
- 建议默认 2200 字符 ≈ 550-700 tokens（中文）

### 记忆压缩策略

当 `memory.md` 接近 `charLimit` 时，按以下优先级释放空间：

1. **archived 条目最先移除**（已被归档 = 已不重要）
2. **按时间从旧到新**：最旧的条目先移除
3. **snapshot 来源的条目**：优先保留（snapshot 是有意识写入的精华）
4. **压缩后保留**：至少保留最近 N 条（可配置 `minEntries`，默认 5）

## 用户体验

| 模式 | 用户感知 | 模型行为 |
|---|---|---|
| 关闭 | 对话中完全没有记忆相关工具 | 完全忽略记忆，每次从零开始 |
| 只读 | 工具栏里只出现「读取记忆」 | 对话开头自动读取记忆重建认知；识别到重要发现时提醒用户（但无法写入） |
| 可修改 | 6 个记忆工具全部可见 | 自主 Snapshot；精确 write/update/archive/delete；对话开头 read 重建上下文 |
