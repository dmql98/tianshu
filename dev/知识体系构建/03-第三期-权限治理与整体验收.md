# 第三期：权限治理与整体验收

## 1. 本期目标

本期不新增第三种知识形态，也不重构前两期。只完成跨模块的权限、工具装配、审计、备份、删除、评测和最终体验收。

角色记忆与文件知识库继续保持独立：

- Memory Snapshot 是角色固定上下文的一部分。
- 角色自己的长尾记忆通过 character_memory_search。
- 组内授权记忆通过 group_memory_search。
- 文件资料通过 knowledge_search/read/list_sources。
- CodeGraph/Graphify 继续使用现有工具。

## 2. Character Tool Loadout

角色最终工具集合按权限装配：

    Own Memory Search
    Group Memory Search
    Knowledge Search / Read / List
    Existing CodeGraph / Graphify
    Existing Skills and MCP Tools

工具是否出现取决于角色配置和 Binding。禁止把组记忆或知识库正文默认注入系统提示词。

## 3. 权限矩阵

至少覆盖：

- 角色读取自己的 private/group 记忆。
- 角色不能读取其他角色 private 记忆。
- 角色只有 groupReadPermission 时才能读取同组 group 记忆。
- 不同组之间默认隔离。
- KnowledgeSource 必须通过角色/组/会话 Binding 授权。
- 用户管理界面拥有查看和撤销权限。

权限过滤发生在 Repository/Retrieval 层，不能依赖模型遵守提示词。

## 4. 上下文稳定性

系统级检查：

- 同一 Session 的 Soul、Memory Snapshot、Tool Guide 保持稳定。
- Tool 结果追加在固定前缀之后。
- 新记忆不会偷偷修改已开始会话。
- 新知识版本不会重写历史 Tool Message。
- 恢复会话使用原 snapshot_id 和当时记录的上下文配置。

提供 Context Inspector，但不展示模型隐藏推理。

Inspector 至少显示：

- 当前角色和 Session Snapshot。
- 固定注入内容及 token。
- 可用工具和权限来源。
- Memory/Knowledge 工具命中及引用。
- 被权限、过期、冲突或预算排除的结果。

## 5. 统一审计

记录：

- 谁创建、批准、修改、删除记忆。
- 哪个角色通过组工具读取了哪个角色的记忆。
- 哪个 Run 搜索和读取了哪些知识片段。
- Provider 是否向外部发送了文本。
- 删除和迁移任务结果。

审计日志不保存 Provider 密钥和不必要的完整敏感正文。

## 6. 删除

删除作用域：

- 单条/主题/角色记忆。
- 角色所有记忆。
- 知识源或版本。
- 角色组共享授权。

软删除必须立即阻断 Snapshot、FTS、向量和工具读取；后台物理清理生成 deletion report。

删除角色时必须由用户选择：

- 同时删除其记忆。
- 保留为不可绑定归档。
- 转移明确设为 group 的记忆。

不得自动把角色 private 记忆转为组共享。

## 7. 导入、导出与备份

Memory 和 Knowledge 使用同一导出容器，但保持独立清单：

- memories.jsonl、snapshots、sources。
- knowledge originals、Markdown、source-map、versions。
- bindings、policies、checksums。

默认不导出密钥和可重建向量。

备份同时覆盖 SQLite 和资产目录；恢复后重建 FTS/向量，并实际验证随机样本和引用。

## 8. 评测

### Memory

- 明确记住、明确忘记。
- 偏好更新、重复强化、事实冲突。
- 当前会话 Snapshot 不变。
- 新会话跨会话生效。
- 旧会话恢复仍用旧 Snapshot。
- 私有和组共享权限。

### Knowledge

- 格式转换和 source anchors。
- Recall@K、MRR、引用正确率。
- lexical-only、向量和 RRF。
- Provider 故障、索引重建和删除。

### 系统

- 跨角色、跨组和未绑定知识越权率为零。
- 稳定提示词前缀的哈希一致性。
- Job 重启恢复。
- 备份恢复。
- Windows 安装包和升级。

## 9. 最终验收场景

1. 角色 A 在会话中获知用户偏好。
2. 当前会话后续轮次的 snapshot hash 不变。
3. 会话结束触发提取并生成新 Snapshot。
4. 新建角色 A 会话，能够使用新偏好。
5. 恢复旧会话，仍使用旧 Snapshot。
6. 角色 B 无权限时无法读取 A 的 private 记忆。
7. 用户把某条 A 记忆设为 group，B 通过 group_memory_search 读取，不启动 A。
8. B 通过 Binding 搜索知识文件并得到原文件引用。
9. B 继续使用现有 CodeGraph/Graphify 查询代码，没有走 Knowledge DB。
10. 用户删除该记忆和知识源，所有索引及工具立即不可见。

## 10. 发布门禁

- 前两期的最终 Schema 不再变化。
- 没有临时表、双写路径或重复检索服务。
- 当前数据各自只迁移一次。
- 所有越权测试通过。
- 缓存稳定性测试通过。
- 删除和恢复完成真实演练。
- UI 清楚区分“角色记忆”“组内授权记忆”“文件知识库”“代码图谱”。

- Memory、Knowledge 和系统评测套件。
- 安装升级、故障处理和回滚手册。
