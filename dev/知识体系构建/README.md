# 天枢记忆与知识体系执行索引

## 当前确定的建设顺序

先完整解决“每个角色自己的记忆”，再建设独立知识库，最后只做跨模块治理和发布收口。

每一期都是一个边界完整的垂直模块，不是“先建临时数据库、下一期再推翻”：

1. [第一期：角色私有记忆与跨会话机制](./01-第一期-角色私有记忆与跨会话机制.md)
2. [第二期：独立文件知识库](./02-第二期-独立文件知识库.md)
3. [第三期：权限治理与整体验收](./03-第三期-权限治理与整体验收.md)

总体领域边界见 [知识体系总体设计](./00-知识体系总体设计.md)。

## 第一期的核心产品规则

- 记忆首先属于角色，不默认属于全局或知识库。
- 新会话创建时生成并固定一个角色 Memory Snapshot。
- Snapshot 作为系统提示词的稳定前缀注入；同一会话生命周期内不自动变化。
- 会话过程中产生的新记忆写入候选/记忆库，但不修改当前会话 Snapshot。
- 新记忆从下一个新会话开始生效；当前会话依靠已有对话上下文理解刚发生的内容。
- 恢复旧会话时继续使用原 Snapshot，不自动升级到最新版。
- 角色可通过工具按需读取组内其他角色被授权的记忆，不启动其他角色，不默认注入组记忆。

## 三个系统严格分开

| 系统 | 保存什么 | 使用方式 |
|---|---|---|
| Character Memory | 角色经历、用户偏好、决定、约束、事件 | 新会话 Snapshot + 按需检索 |
| Knowledge Base | 用户上传的资料、Markdown、分块和索引 | 独立知识工具 |
| CodeGraph / Graphify | 现有代码结构和调用图 | 继续使用现有工具 |

Memory 与 Knowledge 可以复用后台任务、Embedding Provider 等基础设施，但不得共用事实表、状态机或管理页面。CodeGraph/Graphify 不重新导入知识库，不重复建设代码索引。

## 开发原则

- 每一期开始时冻结该领域最终 Schema、接口和状态机，并在当期完整实现。
- 不创建下期要迁移的临时表或临时公共接口。
- 当前真实数据只迁移到该领域的最终结构一次。
- 记忆写入和 Snapshot 发布分离。
- 记忆修改采用版本化或 supersede，不原地改掉历史证据。
- 知识原文件不可变，Markdown 是运行工作格式。
- 组内记忆默认私有；只有明确的组共享权限才能被其他角色工具读取。
- 所有动态工具结果都位于稳定系统提示词之后，不破坏固定前缀。

## Agent 执行要求

执行 Agent 必须先阅读总体设计和当期文件，并按仓库 AGENTS.md 使用 CodeGraph/Graphify 确认代码调用链。

每期交付必须包含：

- 最终数据迁移。
- 后端、UI 和 Agent Loop 接入。
- 权限、失败、重试、删除和恢复。
- 单元、契约、集成和最小 E2E 测试。
- 实际运行验证和回滚说明。

不得把“页面能打开”“表已经创建”或“以后再接入 Agent”作为完成。
