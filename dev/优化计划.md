# 单聊拉起子 Agent 开发草案（定稿）

> 范围：仅覆盖**当前单会话（单独对话）**通过 `delegate_to_agent` 拉起子 agent。群聊（多带 soul 智能体协作）为独立功能，不在本文，后续单独文件规划。
> 本文为定稿开发草案，所有决策已确认。M1 为待实施项，P2–P5 为后续路线。

---

## 0. 配置模型（核心决策）

**角色级「工作帮手」= 该角色的默认可委托白名单**，存在角色配置里，创建该角色会话时带入。

```
character.json
  └ helpers: string[]          // 工作帮手，系统默认 ['worker']
        ↓ 创建会话(character_id=X)
session.targets = X.helpers    // 本会话可委托白名单（实例，初始=模板）
        ↓ 会话侧边「帮手栏」可编辑（增/删）
outer.ts 过滤: targets.includes(c.id)
        ↓ 模型 delegate 时看到 | targets: 后缀
```

- **`worker` 角色**：`role=sub`，空 `soul`/`user`/`memory`，memory 不开，通用 `tools`。它是轻量体。
- **轻量化靠数据，不靠代码**：`sub-agent.ts` 注入逻辑是「有值才注入」（`if (charContent.soul) ...`），worker 空人格 → 子 agent 天然无人格。***P0 改 `sub-agent.ts` 代码的方案撤销***，零代码改动实现轻量。
- **系统默认 `helpers = ['worker']`**（不含自己、不含其他）。角色可在「工作帮手」配置区手动加自己/其他角色。
- **worker 可删**：从 `helpers` 或会话 `targets` 删掉 worker → `targets` 为空 → 模型无 `targets` → **不能拉起子 agent**（无帮手即不拉）。
- **移除 `active_group`**：单值组匹配弃用，统一用 `targets` array。组概念仅作前端「批量加入 targets」的便捷手段（读角色 `groups` 标签展开 ids），后端不过 group。

## 1. M1 — 实施清单（单聊可拉起轻量 worker）

> 目标：单聊默认能拉起 worker；用户可在角色页配工作帮手、在会话侧边管帮手。零代码轻量化（worker 空人格）。

### 1.1 建 `worker` 角色
- **文件**：`devdata/characters/worker/character.json`（新）
- **内容**：
  ```jsonc
  {
    "id": "worker", "name": "干活助手", "role": "sub",
    "groups": [], "soul": "", "user": "", "memory": "",
    "tools": ["read","grep","glob","bash","fs","websearch"],  // 通用集，approval 收紧
    "maxSteps": 50
  }
  ```
- **验证**：角色加载成功；`role=sub` 可被委托。

### 1.2 角色 `character.json` 加 `helpers` 字段
- **文件**：所有 `devdata/characters/*/character.json` + 角色加载逻辑
- **内容**：新增 `helpers: string[]`，系统默认 `['worker']`（角色加载时若缺 `helpers` 则兜底 `['worker']`，或迁移脚本补写）。
- **验证**：ram 等角色 `helpers` 默认 `['worker']`；用户可在角色页改成 `['ram','worker']`。

### 1.3 数据层 `targets`
- **文件**：`sessions` 表 schema + 会话创建逻辑
- **改动**：`active_group` 列 → `targets`（JSON/text array）；创建会话时 `targets = character.helpers`（默认 `['worker']`）。
- **验证**：新建会话 `targets` 初始为角色 `helpers`；旧 `active_group` 不再使用。

### 1.4 `outer.ts` 过滤 + 描述
- **文件**：`web/server/src/agent/outer.ts`（L163-183 delegates 计算）、`loop/control-registry.ts`（L119-120 描述）
- **改动**：
  ```ts
  // 过滤：去"自己恒过"、去 active_group 组匹配，纯 targets
  const targets = session.targets ?? ['worker']
  if (targets.includes(c.id)) return true
  return false
  // 描述后缀：| targets: id(name) 读 session.targets
  ```
- **P1 描述引导**：`delegate_to_agent` 描述补场景（上下文隔离调研 / 独立视角验证 / 预算不足长任务）；`targets` 为空时注明「未配置可委托角色，请勿调用」。
- **验证**：类型检查通过；单聊 `targets=['worker']` 时模型看到 `targets: worker(干活助手)`；删光后描述提示不可调用。

### 1.5 前端 — 角色页「工作帮手」配置区
- **文件**：角色管理页组件（角色列表旁/下新增区域）
- **改动**：编辑当前角色的 `helpers`——角色多选（含自己、含所有角色、含 `worker`），默认勾 `worker`；保存写回 `character.json`。
- **验证**：ram 页配 `['ram','worker']` 保存后，新建 ram 会话 `targets=['ram','worker']`。

### 1.6 前端 — 会话侧边「帮手栏」
- **文件**：会话侧边详情面板组件（新增「帮手栏」）
- **改动**：读 `session.targets` → 查角色 → 渲染圆形头像 + 名称，布局 `[头像][头像][头像][+]`；末尾 `+` 打开角色选择器添加；鼠标悬停头像浮出 `x`，点击从本会话 `targets` 删除（删 worker 后 `targets` 空，UI 提示「无帮手，无法拉起子 agent」）。
- **验证**：帮手栏显示当前 targets 角色；`+` 添加生效；hover `x` 删除生效（含删 worker → 空态提示）。

### 1.7 M1 验收
- 类型检查（`web/server`）+ 构建（`web/client`）通过。
- 新建会话默认 `targets=['worker']`；模型对话「拉起子 agent 去…」→ delegate 给 worker → 轻量子 agent 跑完回传。
- 角色页改 helpers、会话帮手栏增删均生效；删光 worker → 不可拉子 agent。

## 1.8 边界：层级硬控（现状已控，M1 不改）

- **只能两层（父 → 子），无孙代理**。`MAX_DEPTH` 按决策**硬编码为 1**。
- 三层保险（均已在代码中，M1 无需新增）：
  1. `sub-agent.ts` L152：建子会话时 `toolDefs = getCharacterToolDefinitions(targetChar.tools).filter(t => t.function.name !== 'delegate_to_agent')`——按「是否子会话」过滤，**不论 targetChar 是 `sub` 还是 `both`，子代理均无 `delegate_to_agent` 工具**，不能再生子代理。
  2. `control-router`：子会话（`parent_id≠null`）的 delegate 请求直接拒绝（孙代理结构上不可能）。
  3. `MAX_DEPTH=1`：`depth>=1` 抛错。
- 即 `both` 角色在**顶层会话**可 delegate（拉子），一旦成为子代理即被剥离 delegate 工具，与 `sub`/`worker` 同为终点节点。群聊若需多 agent 协作，在独立功能里放开，不影响此处。
