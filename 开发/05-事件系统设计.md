# 天枢 — 事件系统设计

> 文档版本：v0.1 | 更新日期：2026-07-20

---

## 一、设计目标

1. **主动出击** — Agent 不再等人开口，事件引擎在对的时机主动触发星官行为
2. **游戏化留存** — 事件是收集养成体系的核心驱动力：解锁、羁绊、连珠、彩蛋
3. **可扩展** — 事件类型可注册，第三方星官可定义自定义事件
4. **不影响性能** — 事件检测在后台异步运行，不阻塞对话 Loop

## 二、事件引擎架构

```
┌─────────────────────────────────────────────────────────────┐
│                        事件引擎                               │
│                                                             │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │ 事件触发器    │  │ 事件匹配器  │  │  事件执行器          │  │
│  │              │  │             │  │                     │  │
│  │ 定时器       │  │ 按事件类型  │  │  → 唤醒星官         │  │
│  │ 使用统计     │  │ 匹配对应    │  │  → 发送消息体       │  │
│  │ 系统钩子     │  │ 星官和动作  │  │  → 播放动效         │  │
│  │ 外部信号     │  │             │  │  → 记录命盘         │  │
│  └──────┬───────┘  └──────┬──────┘  └──────────┬──────────┘  │
│         │                │                     │            │
│         ▼                ▼                     ▼            │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │                    事件队列（EventQueue）                  │ │
│  │  FIFO 队列，防止事件风暴。高优先级事件插队。               │ │
│  └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 事件生命周期

```
触发 → 匹配 → 入队 → 执行 → 记录
  │       │       │       │       │
  │       │       │       │       └─ 写入命盘 + 更新星官状态
  │       │       │       └───────── 调用 StarAction
  │       │       └────────────────── 排队（防风暴）
  │       └────────────────────────── 匹配事件类型 → 星官
  └────────────────────────────────── 定时器/统计/钩子
```

## 三、六种事件类型

### 3.1 定时事件（TimerEvent）

| 属性 | 值 |
|------|-----|
| 触发条件 | 到达预设时间（cron 表达式或绝对时间） |
| 响应动作 | 指定星官主动发起对话 |
| 频率 | 一次性 / 每日 / 每周 / 自定义 cron |
| 示例 | 每日 08:00 长庚推送晨间简报 |

```typescript
interface TimerEvent {
  type: 'timer'
  id: string
  starId: string            // 执行的星官
  cron: string              // cron 表达式
  prompt: string            // 星官的对话内容模板
  enabled: boolean
  lastTriggeredAt?: number
}
```

### 3.2 开机事件（BootEvent）

| 属性 | 值 |
|------|-----|
| 触发条件 | 应用启动 |
| 响应动作 | 收集待办信息并展示 |
| 特殊规则 | 开机后延迟 2 秒触发（等 UI 就绪），不在 splash 阶段触发 |

```typescript
interface BootEvent {
  type: 'boot'
  starId: string            // 默认长庚
  // 自动注入：收集上次关闭后的未完成任务
}
```

### 3.3 进化事件（EvolutionEvent）

| 属性 | 值 |
|------|-----|
| 触发条件 | 同一类型任务 / 同一工具调用频率达到阈值 |
| 响应动作 | 星官觉醒新能力 / 优化技能精度 |
| 阈值 | 同一工具调用 > 50 次 → 生成对应 Skill |
| 示例 | 天璇的 `bash` 调用超过 50 次 → 自动生成 `deploy-script` skill |

```typescript
interface EvolutionEvent {
  type: 'evolution'
  starId: string
  triggerTool: string       // 触发的工具名
  triggerCount: number      // 触发时的调用次数
  evolvedSkill: string      // 生成的技能名
}

// 进化条件判断
function checkEvolution(starId: string, toolName: string, count: number): EvolutionEvent | null {
  const threshold = EVOLUTION_THRESHOLDS[toolName] ?? 50
  if (count >= threshold && count % threshold === 0) {
    return {
      type: 'evolution',
      starId,
      triggerTool: toolName,
      triggerCount: count,
      evolvedSkill: `auto_${toolName}_${Math.floor(count / threshold)}`,
    }
  }
  return null
}
```

### 3.4 回归事件（ReturnEvent）

| 属性 | 值 |
|------|-----|
| 触发条件 | 星官连续未使用超过 7 天 |
| 响应动作 | 星官主动问候并回溯记忆 |
| 专属苏醒语 | 每个星官不同（见设计书） |

```typescript
interface ReturnEvent {
  type: 'return'
  starId: string
  idleDays: number
  lastActiveAt: number
  // 触发后：状态从 asleep → awakening → active
}
```

### 3.5 羁绊事件（BondEvent）

| 属性 | 值 |
|------|-----|
| 触发条件 | 特定星官组合在短时间内被连续调用 |
| 响应动作 | 多星官协作解锁组合技 |
| 组合表 | 文曲 + 辰星 → "博古通今" / 天璇 + 文曲 → "文武双全" |

```typescript
interface BondEvent {
  type: 'bond'
  bondName: string
  stars: string[]           // 参与组合的星官
  comboDescription: string  // 组合技描述
}

const BOND_RULES: BondRule[] = [
  {
    stars: ['wenqu', 'chenxing'],
    withinMinutes: 30,
    name: '博古通今',
    description: '自动构建知识图谱 + 输出文档',
  },
  {
    stars: ['tianxuan', 'wenqu'],
    withinMinutes: 30,
    name: '文武双全',
    description: '代码 + 文档一次性输出',
  },
]

// 检测逻辑
function checkBonds(recentCalls: { starId: string; time: number }[]): BondEvent | null {
  for (const rule of BOND_RULES) {
    const matched = rule.stars.every(starId =>
      recentCalls.some(c => c.starId === starId && Date.now() - c.time < rule.withinMinutes * 60_000)
    )
    if (matched) return { type: 'bond', bondName: rule.name, stars: rule.stars, comboDescription: rule.description }
  }
  return null
}
```

### 3.6 连珠事件（CometEvent）

| 属性 | 值 |
|------|-----|
| 触发条件 | 四星官以上同时后台运算 |
| 响应动作 | 界面触发"七星连珠"特效，释放一次免排队的最高算力权限 |
| 冷却 | 24 小时内不重复触发 |

```typescript
interface CometEvent {
  type: 'comet'
  activeStarCount: number
  // 特效：所有星官剪影短暂现身
  // 权限：一次免排队 max_tier 模型调用
}
```

## 五、前端可视化

### 5.1 事件触发流

```
事件触发
  │
  ├── 1. 检查前端是否在活跃对话中
  │     ├── 是 → 直接在对话流中插入事件消息
  │     └── 否 → 弹出事件通知 + 星官图标动效
  │
  ├── 2. 播放对应动效
  │     ├── timer/boot: 星官图标呼吸光晕
  │     ├── evolution: 星官图标升级特效（金光 + 粒子）
  │     ├── return:    石像龟裂 → 觉醒全流程
  │     ├── bond:      双星官图标靠近 + 融合动画
  │     └── comet:     全屏"七星连珠"粒子特效
  │
  └── 3. 记录到命盘
```

## 六、防事件风暴

```typescript
class EventQueue {
  private queue: EventRecord[] = []
  private processing = false
  private lastTimestamps: Map<string, number> = new Map()

  // 同一类型事件 5 秒内不重复
  private COOLDOWN = 5_000

  // 高优先级事件插队
  private PRIORITY: Record<string, number> = {
    comet: 100,
    bond: 80,
    return: 60,
    evolution: 40,
    boot: 20,
    timer: 10,
  }

  async push(event: EventRecord): Promise<void> {
    const last = this.lastTimestamps.get(event.type) ?? 0
    if (Date.now() - last < this.COOLDOWN) return  // 静默丢弃
    this.lastTimestamps.set(event.type, Date.now())

    // 按优先级插入
    const priority = this.PRIORITY[event.type] ?? 0
    const insertAt = this.queue.findIndex(e => (this.PRIORITY[e.type] ?? 0) < priority)
    if (insertAt === -1) {
      this.queue.push(event)
    } else {
      this.queue.splice(insertAt, 0, event)
    }
    if (!this.processing) this.process()
  }
}
```

## 七、与 LeAgent 的事件对比

| 维度 | LeAgent | 天枢 |
|------|---------|------|
| 事件机制 | 声明式 YAML 规则引擎（if → then） | **六种游戏化事件类型** |
| 触发方式 | 手动配置规则 | **自动检测 + 定时 + 统计 + 钩子** |
| 响应 | 执行工具 / 调用 webhook | **唤醒星官 + 播放动画 + 解锁能力** |
| 留存 | ❌ 无 | **羁绊、连珠、命盘、彩蛋驱动留存** |
| 可视化 | ❌ 无 | **每类事件有专属动效** |
| UGC | YAML 规则可编写 | 事件类型可注册 |
