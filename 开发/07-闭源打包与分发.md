# 天枢 — 闭源打包与分发策略

> 文档版本：v0.1 | 更新日期：2026-07-20

---

## 一、威胁模型

天枢是闭源桌面软件，后端代码（TypeScript 编译为 JS）跑在用户机器上。面临的威胁：

| 威胁 | 等级 | 说明 |
|------|------|------|
| 直接解压 ASAR 读源码 | 🔴 高 | ASAR 是 zip 格式，任何人可以解压看到所有 JS |
| 复制安装包给他人 | 🔴 高 | 没有授权机制，谁拿到安装包都能用 |
| 修改源码绕过授权 | 🟡 中 | 改了 JS 逻辑就可以跳过 license 检查 |
| 逆向工程 API 通信 | 🟢 低 | 走 HTTPS + WebSocket，但 key 在客户端仍可抓包 |
| 破解 Electron 壳 | 🟢 低 | 可 dump 内存中解密后的代码 |

## 二、分层保护策略

### 2.1 后端代码保护

后端 JS 代码用 `javascript-obfuscator`（Yi-Lin 已验证）。

```javascript
// electron-builder.yml 的 extraResources 中加入构建步骤
// 在复制到 extraResources 之前执行 obfuscate

"extraResources": [
  {
    "from": "../backend/dist",
    "to": "backend",
    "filter": ["**/*"],
    "transform": {
      "**/*.js": "javascript-obfuscator"  // 每个 .js 文件经过混淆
    }
  }
]
```

混淆配置（Yi-Lin 已验证的参数）：

```json
{
  "compact": true,
  "controlFlowFlattening": true,
  "controlFlowFlatteningThreshold": 0.75,
  "deadCodeInjection": true,
  "deadCodeInjectionThreshold": 0.4,
  "stringArray": true,
  "stringArrayEncoding": ["base64"],
  "stringArrayThreshold": 0.75,
  "transformObjectKeys": true,
  "unicodeEscapeSequence": false
}
```

**已知局限**：混淆不防专业逆向，但可以挡住 99% 的 casual 用户。如果要防专业逆向，需要走 V8 字节码或 WebAssembly，成本太高——天枢 MVP 阶段不需要。

### 2.2 前端代码保护

Vite 构建本身就做了 minify + tree-shaking，加上 React 的 JSX 编译，可读性已经很低。额外加固：

```typescript
// vite.config.ts
export default defineConfig({
  build: {
    minify: 'terser',
    terserOptions: {
      compress: { drop_console: true, drop_debugger: true },
      output: { comments: false },
    },
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom', 'framer-motion'],
        },
      },
    },
  },
})
```

### 2.3 ASAR 加密

Electron 生态的标准方案是用 `electron-vite` / `@electron/asar` 打包。对于闭源场景，有几种选择：

| 方案 | 保护强度 | 性能影响 | 实施复杂度 |
|------|---------|---------|-----------|
| 默认 asar | 🟡 低 — 可被解压 | 无 | 零 |
| **asar 加密（@electron/asar encrypt）** | 🟡 中 — 防 casual | 启动略慢 | 低 |
| 核晶方案（V8 沙盒 + 分割） | 🟢 高 | 启动慢 | 高 |
| 混合：混淆 + 加密 asar | 🟡 中 — 性价比最优 | 可接受 | 低 |

推荐方案：**混淆 + 加密 ASAR**。

```yaml
# electron-builder.yml
asar: true
asarUnpack:
  - "**/*.node"              # 原生模块不解密，直接打
  - "backend/runtime/**"     # 运行时不解密
```

### 2.4 授权与激活（License）

闭源桌面软件需要一个简单的 license 机制来防止随意分发。

#### 授权架构

```
用户购买 → 获取 license key
  │
  ├── 首次启动：输入 license key
  ├── 客户端将机器指纹 + license key 发送到授权服务器
  ├── 授权服务器验证：
  │     ├── key 未过期
  │     ├── key 未超过激活数
  │     └── 返回签名 token（JWT）
  ├── 客户端保存 token 到 electron-store
  └── 每次启动时验证本地 token（离线可工作 N 天）
```

#### 授权服务器

轻量 HTTP API，可以用 Cloudflare Workers 或 Vercel Edge Functions 部署，成本几乎为零：

```typescript
// POST /api/license/activate
interface ActivateRequest {
  licenseKey: string
  machineFingerprint: string
}

interface ActivateResponse {
  ok: boolean
  token?: string          // JWT，过期时间 30 天
  expiresAt?: number
  error?: string
}

// POST /api/license/verify
interface VerifyRequest {
  token: string
  machineFingerprint: string
}

interface VerifyResponse {
  ok: boolean
  renewToken?: string     // 如果快过期了，续一个
}
```

#### 离线容灾

```typescript
// 用户不可能永远在线
const OFFLINE_GRACE_DAYS = 7

function getRemainingOfflineDays(token: StoredToken): number {
  if (!token) return 0
  const daysSinceLastVerify = (Date.now() - token.lastVerifiedAt) / 86_400_000
  return Math.max(0, OFFLINE_GRACE_DAYS - daysSinceLastVerify)
}
```

#### License key 生成

```typescript
// 用 HMAC 签名，无需数据库也能验证 key 真伪
function generateLicenseKey(payload: {
  plan: 'trial' | 'standard' | 'pro'
  days: number
  maxActivations: number
}): string {
  const data = `${payload.plan}|${payload.days}|${payload.maxActivations}|${Date.now()}`
  const sig = crypto.createHmac('sha256', LICENSE_SECRET).update(data).digest('hex').slice(0, 8)
  return Buffer.from(`${data}|${sig}`).toString('base64')
}

function verifyLicenseKey(key: string): { valid: boolean; payload?: any } {
  try {
    const decoded = Buffer.from(key, 'base64').toString()
    const parts = decoded.split('|')
    const sig = parts.pop()
    const data = parts.join('|')
    const expected = crypto.createHmac('sha256', LICENSE_SECRET).update(data).digest('hex').slice(0, 8)
    return { valid: sig === expected, payload: parts }
  } catch {
    return { valid: false }
  }
}
```

## 三、分发策略

### 3.1 安装包分发

| 渠道 | 适合阶段 | 说明 |
|------|---------|------|
| **私有 S3 / Cloudflare R2** | MVP + 早期 | 安装包上传到 R2，链接付费后发送。成本极低。 |
| **Gumroad / 面包多** | 发布期 | 国内可用面包多，国外 Gumroad。处理支付 + 自动发送下载链接。 |
| **自建商店 API** | 规模期 | 自己的支付 + license + 下载闭环。 |

### 3.2 自动更新

不能再用公开 GitHub Releases。改用私有更新服务：

```yaml
# electron-builder.yml
publish:
  provider: generic
  url: https://update.tianshu.dev/download/  # 私有更新服务器
  channel: latest
```

更新服务器只需要一个静态文件结构：

```
/download/
  latest.yml                    # electron-updater 的版本清单
  latest.yml.sig               # 签名（可选）
  TianShu-Setup-1.0.0.exe      # 安装包
  TianShu-Setup-1.0.1.exe
  TianShu-1.0.0.dmg
  TianShu-1.0.1.dmg
  TianShu-1.0.0.AppImage
  TianShu-1.0.1.AppImage
```

`latest.yml` 内容：

```yaml
version: 1.0.1
files:
  - url: TianShu-Setup-1.0.1.exe
    sha512: ...  # SHA-512 hash
    size: 85236456
  - url: TianShu-1.0.1.dmg
    sha512: ...
    size: 78452123
releaseDate: '2026-08-15T10:00:00.000Z'
```

更新服务器可以用 Cloudflare Pages 或 R2 的静态托管，一个月几块钱。

## 四、安装包完整性

```typescript
// 每次启动验证自身完整性
async function verifyIntegrity(): Promise<boolean> {
  if (process.env.NODE_ENV === 'development') return true

  const appPath = app.getAppPath()
  const expectedHash = await fetchExpectedHash()  // 从授权服务器获取
  const actualHash = await hashDirectory(appPath)  // 计算本地 hash
  return expectedHash === actualHash
}
```

## 五、与 Yi-Lin 的打包对比

| 维度 | Yi-Lin | 天枢 |
|------|--------|------|
| 开源 | ✅ 开源 | ❌ **闭源** |
| 代码保护 | javascript-obfuscator 混淆服务端 | 混淆 + **ASAR 加密** |
| 授权 | 无 | **License key + 机器指纹 + JWT** |
| 分发 | GitHub Releases 公开下载 | **私有 R2 / Gumroad** |
| 更新 | 无自动更新 | electron-updater + **私有更新服务器** |
| 离线容灾 | — | **7 天离线宽限** |
| 安装包完整性 | 无 | **启动时完整性校验** |

## 六、推荐 MVP 阶段方案

| 项目 | 方案 |
|------|------|
| 代码保护 | javascript-obfuscator（后端）+ Vite minify（前端） |
| ASAR | 默认加密 |
| License | simple HMAC key + 手动验证（MVP 不发正式版前不用部署授权服务器） |
| 分发 | 初期直接发安装包链接（微信/网盘），上量后用 Gumroad |
| 更新 | MVP 阶段不实现，Phase 3 加 |
| 价格 | 未定，建议先出 MVP 再定价 |
