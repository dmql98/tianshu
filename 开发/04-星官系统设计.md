# 天枢 — 星官系统设计

> 文档版本：v0.1 | 更新日期：2026-07-20

---

## 一、设计目标

1. **人格独立** — 每个星官是独立的 Agent 实例，拥有专属工具集、历史、记忆、权限、语气
2. **上下文纯净** — 星官之间不共享历史，跨星官协作只传摘要，不传全量消息
3. **紫微路由** — 紫微作为超级 Agent 可拉起任意星官做子 Agent，支持委托/协作/咨询三种模式
4. **织女造星** — UGC 接口让用户自定义星官，挂载到空置星位

### 2.2 星官注册中心（运行时）

```typescript
interface StarDefinition {
  id: string
  name: string
  title: string
  description: string
  color: string
  element: 'wood' | 'fire' | 'earth' | 'metal' | 'water'

  // 核心——工具白名单
  tools: string[]

  // 记忆配置
  memory: {
    episodic: boolean       // 是否记录情景记忆
    semantic: boolean       // 是否参与语义记忆共享
    procedural: boolean     // 是否记录程序记忆
    charLimit: number       // 情景记忆上限（字符）
  }

  // 星官状态
  status: 'stone' | 'awakening' | 'active' | 'asleep'
  // stone:    未解锁（暗色石像）
  // awakening: 正在觉醒动画中
  // active:   活跃
  // asleep:   长眠（7天未调用）

  lastActiveAt: number | null
  totalCalls: number
  unlockCondition?: { type: string; value: number }
}
```

## 三、星官生命周期

```
                ┌──────────┐
                │  石像     │  ← 未解锁 / 从未使用
                └────┬─────┘
                     │ 首次使用 / 回归事件触发
                     ▼
                ┌──────────┐
                │  觉醒中   │  ← 觉醒动画播放（3s）
                └────┬─────┘
                     │ 动画完成
                     ▼
                ┌──────────┐
           ┌─── │  活跃     │ ───┐
           │    └──────────┘    │
           │                    │ 连续 7 天未调用
           │ 被调用             ▼
           │              ┌──────────┐
           └────────────  │  长眠     │
                          └──────────┘
                               │ 回归事件触发
                               └──→ 觉醒中
```

### 状态转移条件

| 转移 | 触发 | 动作 |
|------|------|------|
| 石像 → 觉醒中 | 用户首次提及 / 路由分配到该星官 | 播放觉醒动画 + 专属苏醒语 |
| 觉醒中 → 活跃 | 动画完成 | 更新 `status`，记录 `lastActiveAt` |
| 活跃 → 长眠 | `lastActiveAt` < now - 7 天 | 图标变灰，覆盖薄尘 CSS 特效 |
| 长眠 → 觉醒中 | 回归事件触发 | 长庚发送问候，触发觉醒流程 |
| 活跃 → 活跃 | 被调用 | 更新 `lastActiveAt` |

## 四、紫微路由协议（详细）

### 4.1 路由触发点

| 触发方式 | 示例 | 处理 |
|---------|------|------|
| 用户直接点名 | `@天璇 写个脚本` | 直接路由到天璇 |
| 紫微自动判断 | `帮我查天气` | 紫微判断意图 → 路由到长庚 |
| 星官内部委托 | 天璇遇到文档需求 → 委托文曲 | 跨星官协议 |
| 群聊 | `紫微，叫文曲和天璇一起` | 紫微拉起多个子 Agent |

### 4.2 自动判断规则

紫微的路由模型只暴露 3-5 个工具：

```typescript
const ZIWEI_TOOLS = [
  'route_to_star',     // 路由到目标星官
  'ask_user',          // 向用户提问以澄清
  'answer_directly',   // 紫微自己回答简单问题
  'start_collaboration', // 拉起多个星官协作
]
```

判断逻辑：

```typescript
async function routeIntent(userInput: string): Promise<RouteDecision> {
  // 1. 用户明确 @ 了星官 → 直接路由
  const mentioned = extractMention(userInput)
  if (mentioned && starRegistry.exists(mentioned)) {
    return { type: 'direct', targetStarId: mentioned }
  }

  // 2. 让紫微的轻量模型判断
  const intent = await ziweiModel.analyze({
    input: userInput,
    tools: ZIWEI_TOOLS,
    context: {
      activeStar: layoutStore.activeStarId,
      recentStars: starStore.getRecent(),
    },
  })

  return intent
}
```

### 4.3 跨星官通信

```
紫微 → 天璇：委托写脚本
  │
  ├── 紫微调用 route_to_star({
  │     target: 'tianxuan',
  │     task: '写一个Python脚本解析CSV并绘制折线图',
  │     context_summary: '用户需要分析销售数据，数据文件在 C:\\Data\\sales.csv',
  │     route_style: 'delegate',
  │   })
  │
  ├── 路由引擎暂停紫微 Loop，拉起天璇 QueryEngine
  │     ├── 天璇的工具集：[read, write, edit, bash, grep, glob]
  │     ├── 天璇的历史：仅天璇过往对话
  │     ├── 当前输入：任务描述 + 上下文摘要（非紫微全量历史）
  │     └── 天璇独立执行 Loop
  │
  ├── 天璇返回结果
  │
  └── 路由引擎将结果注入紫微的上下文（作为工具结果）
      紫微继续执行 → 回复用户
```

### 4.4 上下文摘要协议

```typescript
// 跨星官协作时不传全量历史，只传摘要
interface ContextSummary {
  taskDescription: string       // 任务描述
  relevantFacts: string[]       // 用户相关的语义记忆（跨星官共享）
  fileReferences: string[]      // 涉及的文件路径
  activeWorkspace: string       // 当前工作目录
  turnCount: number             // 当前已执行的轮次
}

// 如何产生摘要
function buildContextSummary(
  messages: Message[],
  semanticMemory: SemanticStore,
): ContextSummary {
  return {
    taskDescription: extractTaskDescription(messages),
    relevantFacts: semanticMemory.query(messages).slice(0, 5),
    fileReferences: extractFileRefs(messages),
    activeWorkspace: getActiveWorkspace(),
    turnCount: messages.length,
  }
}
```

## 五、记忆隔离方案

```
┌─────────────────────────────────────────────────────────────┐
│                    语义记忆（共享）                            │
│  - 用户偏好：喜欢简洁回复、使用中文                             │
│  - 工作区路径：C:\\Projects                                    │
│  - 全局事实：用户名为"阿曜"                                    │
│  - 所有星官可读可写                                           │
├─────────────────────────────────────────────────────────────┤
│           ┌────────────────┐  ┌────────────────┐             │
│           │ 长庚情景记忆    │  │ 天璇情景记忆    │            │
│           │ - 今天查了天气  │  │ - 昨天写了个    │            │
│           │ - 提醒3点开会   │  │   爬虫脚本      │            │
│           └────────────────┘  └────────────────┘             │
│           ┌────────────────┐  ┌────────────────┐             │
│           │ 长庚程序记忆    │  │ 天璇程序记忆    │            │
│           │ - read: 95% ✅ │  │ - bash: 88% ✅ │            │
│           │ - 推荐: 60%    │  │ - write: 92% ✅│            │
│           └────────────────┘  └────────────────┘             │
└─────────────────────────────────────────────────────────────┘
```

### 5.1 检索范围

| 记忆类型 | 范围 | 谁可读 | 谁可写 |
|---------|------|--------|--------|
| 情景 | 按星官隔离 | 仅该星官 | 该星官自己的 Loop |
| 语义 | 全局共享 | 所有星官 | 所有星官 |
| 程序 | 按星官隔离 | 仅该星官 | 该星官自己的 Loop |

### 5.2 星官切换时的记忆传递

当紫微路由切换到天璇时：

```
1. 紫微调用 buildContextSummary() 生成上下文摘要
2. 天璇的 QueryEngine 收到：
   ├── taskDescription + contextSummary（非全量消息）
   ├── 天璇自己的情景记忆（最近 5 条）
   ├── 全局语义记忆（相关事实）
   └── 天璇自己的程序记忆（工具成功率）
3. 天璇执行完毕后：
   ├── 结果返回紫微
   └── 天璇更新自己的情景/程序记忆
4. 如果天璇学到了新事实 → 写入语义记忆（共享）
```

## 六、织女造星（UGC 接口）

通过织女星官创建自定义星官：

```typescript
// 织女暴露的工具
async function createStar(params: {
  name: string
  title: string
  description: string
  color: string
  element: string
  // Prompt
  soul: string          // 人格定义（SOUL.md）
  systemPrompt: string  // 系统提示词
  // 工具绑定
  tools: string[]       // 可选工具白名单
  skills: string[]      // 可选技能
  // 记忆
  memoryLimit: number   // 情景记忆上限
  // 唤醒
  greeting: string      // 觉醒语
  // 可选：挂载到哪个空星位
  slotIndex?: number
}): Promise<StarDefinition>
```

织女内部流程：

```
1. 验证参数（必填项、工具名是否存在、颜色格式）
2. 生成 starId（从 name 自动派生）
3. 在 stars/<starId>/ 下写入 star.json
4. 注册到 StarRegistry
5. 返回新星官信息 → 前端 UI 刷新
```

## 七、与 LeAgent 的角色对比

| 维度 | LeAgent | 天枢 |
|------|---------|------|
| 角色系统 | ❌ 无。一个 agent 处理所有。 | ✅ 十二星官 + UGC |
| 工具分配 | 100+ 工具全量共享 | 每人 3-8 个领域工具 |
| 上下文 | 共享一个历史 | 每人隔离 + 摘要传递 |
| 记忆 | 单例三区记忆 | 情景/程序隔离 + 语义共享 |
| 路由 | 无路由层 | 紫微路由引擎 |
| 协作 | 无多 agent 协作 | delegate / collaborate / consult 三种模式 |
| UGC | ❌ | 织女造星接口 |
| 唤醒/沉睡 | ❌ | 完整生命周期 + 动效渲染 |
