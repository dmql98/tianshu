Tianshu Character Visual System

天枢角色视觉与动画系统开发设计

面向应用内角色动画、用户角色导入、角色资源生成与未来独立桌面角色窗口的一体化技术方案。

文档版本 v1.0 日期 2026-07-30 适用项目 TianShu dev/web 状态 待实施

1. 背景与调研结论

天枢现有角色系统已经覆盖人格、记忆、模型、工具和技能，但角色视觉仍停留在单一头像字段，尚未形成可扩展的资源与动画能力。

当前前端

React 18 + Vite。角色详情页支持上传头像，聊天区尚无正式角色动画组件。

当前后端

Hono + Socket.IO。角色按 characters/<id>/ 分目录存储，适合扩展资源目录。

UI Demo

使用 112 张 720×720 JPEG，以约 24 FPS 替换图片地址，仅能表达单一 idle 动画。

LeAgent 参考

具有动作目录、资源绑定、状态回落、自动行为和 Sprite Sheet 转换，值得复用其分层思路。

重要现状：天枢当前由批处理启动服务端和 Vite，并直接打开浏览器，不提供独立桌面角色窗口。应用内角色动画按浏览器渲染能力建设。

Demo 方案不直接进入生产的原因

  • 大量 JPEG 序列帧占用网络、内存和解码资源，且不支持透明通道。
  • 动画名称、循环方式和播放优先级均被硬编码，无法扩展多个动作。
  • 缺少组件卸载清理、失败回落、低性能模式和减少动态效果支持。
  • 用户必须遵守固定帧文件命名，不适合开放式角色导入。

2. 建设目标与范围边界

2.1 建设目标

  • 在聊天输入区实现与 UI Demo 相近的常驻角色动画。
  • 建立动画、立绘、名称三级视觉能力，角色不必具备完整动画或独立头像。
  • 通过统一状态机响应监听、思考、说话、工具调用、完成和错误事件。
  • 允许用户导入、导出完整角色包，并在不同设备之间迁移。
  • 为 AI 生成角色设定、立绘及动作素材提供统一产物格式。

2.2 第一阶段不做

  • 不在第一阶段接入 Live2D、Spine 或 3D 模型运行时。
  • 不允许角色包携带任意 JavaScript、HTML、插件或可执行文件。
  • 不在现有浏览器版本中模拟真正的桌面置顶、点击穿透能力。
  • 不要求第一阶段直接完成 AI 视频生成服务，只预留生成任务协议。

2.3 设计原则

资源与角色配置分离 状态与渲染分离 多展示面复用 格式可版本化 导入零代码执行 渐进增强

4. 角色视觉领域模型

角色视觉采用渐进增强模式。现有 avatar: string 保留用于兼容，但新增正式的 visual 配置。业务配置只保存资源 ID、立绘裁切参数和动作绑定，不直接保存大体积 Base64。

4.1 视觉能力分级

等级角色拥有的资源主要区域展示头像展示
L2 · 动画角色至少存在一个可播放动作资源优先播放当前语义动作；缺失动作回落至 idle 或立绘默认从立绘裁切；可用独立头像覆盖
L1 · 立绘角色只有静态立绘，没有动作资源显示完整立绘，可叠加轻微 CSS 呼吸效果根据焦点和缩放参数从立绘实时裁切
L0 · 文本角色没有动画、立绘和可用旧头像显示角色名称、名称首字或默认占位样式沿用当前名称首字头像
等级由资源自动推导，不要求用户手动选择：存在有效动作绑定即为 L2；没有动作但存在立绘即为 L1；两者都不存在即为 L0。删除资源后系统应自动降级，补充资源后自动升级。

4.2 数据结构

  assetId: string

  speed?: number
  mirror?: boolean
  fit?: 'contain' | 'cover'

  sprite?: {

export interface CharacterVisual {
  schemaVersion: 1
  /** 可选覆盖项；通常直接使用立绘裁切结果，不要求单独上传头像。 */
  avatarAssetId?: string
  portraitAssetId?: string
  /** 从立绘生成头像时使用的归一化焦点与缩放。 */
  avatarCrop?: {
    focusX: number
    focusY: number
    zoom: number
  }
  defaultMotion?: CharacterMotion
  motions?: Partial<Record<CharacterMotion | string, CharacterMotionBinding>>
  stage?: {
    scale?: number
    anchorX?: number
    anchorY?: number
  }
}
统一回退顺序：当前动作 → idle 动画 → 静态立绘 → 旧 avatar / 独立头像 → 名称首字。其中小尺寸头像优先使用 avatarAssetId；没有独立头像时，使用 avatarCrop 从立绘裁切；连立绘都没有时，保持当前名称首字表现。

4.3 立绘裁切头像

  • focusX、focusY 使用 0–1 的归一化坐标，默认值为 0.5。
  • zoom 默认值为 1，角色编辑器提供拖动立绘和缩放滑杆。
  • 裁切参数只描述取景，不提前生成多份头像文件；列表、消息和输入区通过同一组件渲染。
  • 如果后续需要导出缩略图，服务端可按裁切参数生成缓存，但缓存不是角色数据的唯一来源。
  • 圆形、方形或圆角矩形由具体 UI 表面决定，不能写死在角色资源中。

5. 动画状态体系

5.1 标准动作目录

分类动作触发条件默认循环
基础idle、blink、breathe无更高优先级事件loop
对话listening、thinking、speaking输入聚焦、推理、流式回复loop
执行toolCalling、working工具开始、持续执行loop
结果success、error会话完成或失败once
互动happy、touched、wave点击、双击、主动招呼once
桌面walk、jump、sleep自动行为或用户操作按动作决定

5.2 状态优先级

动作冲突时不按最后触发者简单覆盖，而是使用优先级和可中断规则：

error / permissionRequired                 优先级 100
success                                   优先级 90
toolCalling / working                     优先级 80
speaking                                  优先级 70
thinking                                  优先级 60
listening                                 优先级 40
用户互动 happy / touched / wave           优先级 30
桌宠自动行为 walk / jump                   优先级 20
idle / blink / breathe                    优先级 10

5.3 动作回落

  • toolCalling → working → thinking → idle
  • speaking → thinking → idle
  • success / error → idle，播放完成后自动回落。
  • 自定义动作可声明显式 fallback，但必须防止循环引用。

5.4 自动行为

应用内默认只执行轻量的眨眼、呼吸和偶发招手；空间行为仅在尺寸允许的舞台开启。系统检测到 prefers-reduced-motion 时关闭随机动作和位移动画。

6. 统一 CharacterRenderer

所有展示面必须使用同一个渲染入口，禁止聊天页、详情页和角色卡分别解析资源。

<CharacterRenderer
  character={character}
  motion="thinking"
  surface="chat-input"
  interactive
  onClick={handleCharacterClick}
/>

6.1 组件输入

参数说明
character角色业务数据与 visual 配置。
motion当前语义动作；为空时由控制器选择。
surfacechat-input、detail-preview、card。
interactive是否接收点击、双击、悬停等互动。
qualitylow、normal、high，用于资源选择和帧率控制。

6.2 分级渲染决策

resolveCharacterVisual(character, requestedMotion, surface)
  1. requestedMotion 有有效资源  → 播放该动画
  2. idle 有有效资源             → 播放 idle 动画
  3. portraitAssetId 存在        → 显示静态立绘
  4. avatarAssetId / 旧 avatar   → 显示兼容头像
  5. 以上都不存在                → 显示名称首字

同一决策函数供聊天区、角色列表和详情页复用。小尺寸 surface 在第 3 步使用立绘裁切视图，大尺寸 surface 显示完整立绘。

6.3 渲染适配器

  • StaticImage：PNG、WebP、JPEG，用于头像和静态立绘。
  • AnimatedImage：GIF、Animated WebP，适合用户低门槛导入。
  • Video：WebM、MP4，适合长动作和高压缩比素材；优先推荐带透明通道的 WebM。
  • SpriteSheet：基于 Canvas 或 CSS background-position 播放，支持帧范围和 FPS。
  • FrameSequence：仅作为兼容入口；导入后建议转码，不作为默认发布格式。
  • Live2D / Spine / Rive：第二阶段以后通过按需加载适配器接入。

6.4 播放行为

  • 资源切换应预加载下一动作，避免出现白屏闪烁。
  • once 动作在结束后通知状态机，不在渲染器内硬编码回落动作。
  • 视频默认静音、内联播放，无法自动播放时显示静态预览帧。
  • 组件卸载时必须释放 Object URL、RAF、计时器、Canvas 与视频资源。

7.3 导入流程

  1. 读取 ZIP 中央目录，先检查总大小、文件数量和路径合法性。
  2. 验证 manifest.json 格式、版本与资源声明。
  3. 校验 MIME、扩展名、魔数、像素尺寸、时长和校验值。
  4. 处理角色 ID 冲突：复制为新 ID、覆盖现有角色或取消。
  5. 将资源写入临时目录，全部成功后原子移动到正式角色目录。
  6. 写入 character.json 并返回导入后的角色。

7.4 版本兼容

导入器只接受已知主版本；同主版本的新字段忽略处理。升级通过纯数据迁移完成，不修改原始包。导出始终生成当前最新格式。

8.2 API 草案

方法路径用途

8.3 写入约束

  • 角色 ID 和资源 ID 仅允许安全字符，并经过服务端重新生成或规范化。
  • 上传先写入角色目录内的临时子目录，验证完成后再原子替换。
  • 重命名角色时必须连同 visual、assets 和导出缓存一起移动。
  • 删除角色沿用整个角色目录删除，但 UI 必须进行二次确认。

9. 前端功能设计

9.1 聊天输入区

  • 将 UI Demo 左侧角色位置替换为 CharacterStage。
  • 动画角色默认显示 idle；输入框聚焦或输入时显示 listening。
  • 只有立绘的角色显示静态立绘，可使用不依赖额外素材的轻微呼吸效果。
  • 没有立绘的角色沿用当前名称首字，不强制用户补充视觉资源。
  • 发送后依次响应 thinking → toolCalling/working → speaking → success/error。
  • 单击打开角色快速卡片，双击触发互动动作；支持关闭动画。
  • 当输入区宽度不足时降级为圆形头像，不挤压文本输入区域。

9.2 角色详情页

新增“立绘与动画”标签页，不再要求头像、立绘和动画必须同时提供。上传立绘后即可在头像裁切器中设置焦点与缩放；动画作为可选增强能力继续添加。

实时预览

可切换头像、聊天、详情、桌面四种比例，查看当前视觉等级和回退结果。

资源库

上传、预览、替换和删除图片、动画图片、视频及 Sprite Sheet。

立绘裁切

拖动立绘并调节缩放，设置列表、消息和输入区共用的头像取景。

动作绑定

可选增强；为动作选择资源，配置循环、速度、镜像、适配和回落。

角色包

导入、导出、验证和查看包版本及资源占用。

9.3 Sprite Sheet 工作台

  • 填写列数、行数、帧间距、起止帧和 FPS。
  • 提供透明背景预览、逐帧检查和播放速度调节。
  • 第一版可以直接按 Sprite Sheet 播放，不强制转换 GIF。
  • 允许同一张 Sprite Sheet 的不同帧区间绑定多个动作。

9.4 无障碍与用户设置

  • 遵循系统的减少动态效果设置，并提供应用内总开关。
  • 角色动画不得成为完成主要操作的必要条件。
  • 视频和动画图片提供静态预览；错误信息不能只通过角色动作表达。

10. Agent 运行事件联动

动画状态来源必须统一，不允许各组件通过 DOM 或文本猜测 Agent 状态。与《11-会话与 Agent 运行系统统一架构设计》对齐： 服务端持久化 RunEvent，CharacterPresenceProjector 将运行语义、用户交互和本地自动行为归并为角色表现， 聊天区与角色卡消费同一 Presence 投影。

系统事件角色动作结束条件
输入框聚焦 / 用户输入listening失焦或发送
run.started / run.phase:modelthinking出现文本或工具事件
run.reasoning_deltathinking状态切换
tool.startedtoolCalling进入执行或完成
run.phase:toolsworking工具结果
message.deltaspeaking流结束
run.completedsuccess播放一次后回 idle
run.failederror播放一次后回 idle
approval.requested / run.awaiting_inputlistening 或扩展 request用户决定
 
type CharacterRuntimeVisualState = {
  characterId: string
  characterRevisionId: string
  sessionId?: string
  runId?: string
  motion: CharacterMotion
  source: 'agent' | 'interaction' | 'autopilot'
  priority: number
  since: number
  interruptible: boolean
}

角色 revision 发布后不可变；Run 创建时固定实际 revision。角色资产由角色系统归档和延迟回收， 但历史 Run、事件 Occurrence 或固定 Session 的引用会阻止物理删除。视觉资源不可用时按动画 → 立绘 → 名称降级， 不影响 Run 的业务终态。

12. 用户生成角色能力

角色生成不是新增另一种角色格式，而是生产标准角色包的自动化流程。

12.1 生成流水线

角色设定名称、人格、视觉关键词
→
视觉素材优先立绘，动画按需增强
→
角色包组装校验、预览、导入

12.2 生成阶段

  1. 用户输入自然语言设定，生成角色名称、简介、Soul 和视觉提示词。
  2. 优先生成完整立绘，经用户确认后锁定角色视觉一致性；头像默认从立绘裁切。
  3. 为标准动作生成短视频、动画图片或 Sprite Sheet。
  4. 进行背景透明度、角色一致性、尺寸和循环衔接检查。
  5. 自动建立动作绑定，生成预览和角色包。
  6. 用户在动画工作台调整后正式安装。

12.3 最小可行生成

第一版生成能力只需覆盖“角色设定 + 立绘”，头像从立绘裁切。idle 和其他动作可以逐步生成和补齐；角色没有立绘时也能以名称模式安装和使用。

13. 安全、性能与兼容性

13.1 导入安全

  • 禁止绝对路径、..、符号链接和 ZIP 路径穿越。
  • 禁止 HTML、JavaScript、可执行文件、脚本、动态库和未知模型代码。
  • 同时验证扩展名、声明 MIME 和文件魔数。
  • 限制单文件大小、解压后总大小、文件数量、图片像素和视频时长。
  • 检测压缩比异常，防御 ZIP bomb。
  • 导入失败时清理临时目录，不留下半安装角色。

13.2 建议默认限制

项目默认值说明
角色包压缩大小100 MB桌面端可在设置中提高。
解压后总大小300 MB阻止异常压缩包。
包内文件数量500序列帧兼容时仍有余量。
单张图片像素4096×4096超出时拒绝或生成缩略图。
单动作视频时长30 秒角色动作不应使用长视频。
Sprite Sheet 帧数256超过时建议拆分动作。

13.3 性能策略

  • 聊天页只预加载当前动作和最可能的下一动作。
  • 角色不可见、窗口最小化或标签页隐藏时暂停渲染。
  • 同一资源由浏览器缓存共享，URL 包含资源内容版本。
  • 低性能模式固定在 12–15 FPS，并禁用自动移动行为。
  • 角色卡片只显示静态预览，不同时播放大量动画。

14. 分阶段实施计划

P1

基础资源与应用内动画

建立视觉类型、资源 API、统一渲染器和动作回落；在聊天输入区及角色详情页接入。支持静态图片、GIF/Animated WebP、WebM/MP4。

P2

动画工作台与 Sprite Sheet

动作绑定编辑、实时预览、Sprite Sheet 参数编辑、Agent 状态联动、减少动态效果和性能降级。

P3

角色包导入导出

实现包校验、冲突处理、原子安装、导出、格式迁移和完整安全限制，形成用户可交换的角色生态基础。

P4

角色生成与高级运行时

生成角色设定、立绘和动作素材；按产品需求评估 Live2D、Spine、Rive 或 3D 适配器。

推荐优先级

P1 → P2 → P3 应连续完成，形成完整的应用内角色体验。P4 在应用内体验稳定后推进。

15. 测试方案与验收标准

15.1 单元测试

  • manifest 解析、版本兼容和非法字段拒绝。
  • 动作回落、优先级、不可中断动作和循环引用检测。
  • MIME、路径、文件大小、像素和 ZIP 安全校验。
  • Sprite Sheet 帧坐标、FPS、起止帧计算。
  • 旧 avatar 角色的兼容回落。

15.2 组件测试

  • 每种资源格式能够正确选择渲染适配器。
  • 动作播放一次后通知控制器并正确回落。
  • 切换角色和卸载组件后不残留定时器、RAF、Object URL。
  • 减少动态效果下不播放位移和随机动作。

15.3 API 测试

  • 上传、读取、Range、删除、重命名角色时资源保持完整。
  • 导入失败不产生半安装目录。
  • 角色包导出后可重新导入并保持动作绑定一致。
  • 路径穿越、ZIP bomb、伪造 MIME 和超限资源被拒绝。

15.4 P1 验收标准

  • 只有动画、只有立绘、没有视觉资源三类角色都能正常创建和使用。
  • 动画角色在聊天输入区播放可用动作，并响应 thinking、speaking、working、success、error。
  • 立绘角色可以设置头像焦点和缩放，所有小尺寸头像位置保持一致。
  • 纯文本角色沿用名称首字展示，不出现空白图片或破图。
  • 角色详情页能够展示当前视觉等级、回退链并即时预览。
  • 缺失动作时界面无白屏，能够稳定回落至 idle、静态立绘或名称。
  • 旧角色无需迁移即可继续使用。
  • 前端生产构建和服务端 TypeScript 构建通过。

16. 关键技术决策摘要

决策选择原因
核心抽象语义动作 + 资源绑定Agent 状态不依赖具体文件格式。
资源存储角色目录内文件符合现有架构，易导入、导出和备份。
第一版格式图片、动画图片、视频、Sprite Sheet覆盖面广、实现风险低、用户制作门槛可控。
序列帧 Demo兼容但不作为默认格式资源和解码成本过高。
角色包版本化 ZIP，无代码便于生态交换，同时降低安全风险。
角色生成输出标准角色包复用导入、预览、校验和安装链路。
最终建议：第一轮开发从领域模型、资源 API 和 CharacterRenderer 开始，再接入聊天页。不要先在聊天页复制 Demo 的 setInterval + JPEG 逻辑，否则后续多动作、角色导入都会重复返工。
