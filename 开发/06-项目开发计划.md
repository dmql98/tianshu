# 天枢 — 项目开发计划

> 文档版本：v0.1 | 更新日期：2026-07-20

---

## 一、开发原则

1. **先跑通再优化** — MVP 不追求全量星官和完整事件系统，先让单星官 Loop 跑通
2. **继承不重写** — 从 Yi-Lin 复制已验证的代码（工具系统、Provider 管理、MCP），专注重写 Loop 和前端
3. **垂直切片** — 每个里程碑交付一个端到端可用的功能，而非水平堆积未联调的后端代码
4. **前端与后端并行** — 前端先写静态页面 + mock 数据，后端专注 Loop 和 API

---

## 二、里程碑概览

```
Phase 1: 基石 (MVP)          → 单星官对话可用
Phase 2: 人格管理            → 多星官隔离 + 紫微路由
Phase 3: 桌面端              → Electron 壳 + 打包
Phase 4: 事件驱动            → 六种事件 + 命盘
Phase 5: UGC 与创作者经济    → 织女造星 + 市场
Phase 6: 生产化              → 自动更新 + 遥测 + CI/CD
```

## 三、Phase 1：基石（MVP）

**目标**：一个长庚星官能在 Electron 壳里流畅对话，有国风 UI 雏形

### 后端

| 模块 | 内容 | 预估工时 |
|------|------|---------|
| 项目脚手架 | TypeScript + Fastify + Drizzle + SQLite 项目初始化 | 1d |
| 基础 Loop | `queryLoop()` 核心循环（无压缩/无 checkpoint） | 3d |
| Context 压缩 | microcompact + progressive + autocompact | 2d |
| 工具系统 | 从 Yi-Lin 移植 read/write/edit/bash/grep/glob | 1d |
| Provider 管理 | 从 Yi-Lin 移植 provider_manager | 0.5d |
| 会话 API | CRUD sessions + messages | 1d |
| SSE 流式 | 对话流 SSE 端点 | 1d |

### 前端

| 模块 | 内容 | 工时 |
|------|------|------|
| 项目脚手架 | React 19 + Vite + Tailwind + Zustand + Router | 1d |
| 布局组件 | NavRail + MainContent + StarPanel 骨架 | 1d |
| 对话组件 | MessageList + ChatInput + MarkdownRenderer | 2d |
| 长庚星官 UI | 气泡样式 + 专属色 | 0.5d |
| SSE 对接 | EventSource 连接 + 消息流式渲染 | 1d |
| 毛玻璃背景 | CSS backdrop-filter + Three.js 星轨粒子 | 2d |
| 基础 Electron | main.ts + 窗口 + 加载后端 | 1d |

**Phase 1 总计**：~17 天

**交付物**：
- Electron 窗口打开，显示国风 UI
- 长庚可对话，消息流式渲染
- 毛玻璃背景 + 星轨粒子动效
- 后端 Loop 可处理工具调用

## 十、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| Context 压缩效果不如预期 | 长对话 token 超限 | MVP 先不做压缩，发现问题后再迭代 |
| Three.js 毛玻璃性能差 | 低端机器卡顿 | 检测 FPS 自动降级为纯 CSS |
| 紫微路由误判 | 路由到错误星官 | 路由结果需用户确认（Plan 模式） |
| 事件引擎干扰对话 | 事件在对话中不合时宜触发 | 对话中事件入队延后处理 |
| Python 生态缺失 | 部分工具无法移植 | 坚持 TypeScript，用子进程调用 Python 脚本 |
