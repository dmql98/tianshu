# 天枢 — 技术架构总览

> 文档版本：v0.1 | 更新日期：2026-07-20

---

## 一、设计原则

1. **人格优先** — 架构围绕星官人格隔离设计，而非围绕工具集。每个星官是一个独立的 Agent 实例，拥有专属的上下文、工具、记忆、权限。
2. **生产级工程** — 继承 Yi-Lin 已验证的角色引擎和多 Agent 调度，重写 Loop 为 LeAgent 级别的运行时（Context 压缩、Checkpoint、并发调度、三种恢复路径）。
3. **体验即架构** — 前端渲染层、事件驱动、星轨路由不是后加的皮肤，而是架构的一等公民。
4. **UGC 可扩展** — SDK 层独立，第三方可通过织女接口创建自定义星官，形成创作者经济。

## 三、技术栈

### 后端

| 类别 | 选择 | 理由 |
|------|------|------|
| 运行时 | **Node.js 22+** | 继承 Yi-Lin 的 TypeScript 技术栈，避免 Python 运行时捆绑问题 |
| 框架 | **Fastify / Hono** | 轻量高性能，比 Express 更现代，类型安全 |
| 语言 | **TypeScript 5.x** | 全栈类型统一，继承 Yi-Lin 代码 |
| 数据库 | **SQLite**（默认）→ **PostgreSQL**（扩展） | SQLite 零配置起步，PostgreSQL 支持高并发 |
| ORM | **Drizzle ORM** | 类型安全，轻量，比 Prisma 更可控 |
| 向量存储 | **LanceDB**（本地）/ **Qdrant**（服务化） | LanceDB 嵌入式零依赖，适合桌面端 |
| 流式传输 | **Server-Sent Events + WebSocket** | SSE 适用单向推送，WS 适用双向通信 |

### 前端

| 类别 | 选择 | 理由 |
|------|------|------|
| 框架 | **React 19** | 成熟生态，Framer Motion 动效支持最佳 |
| 语言 | **TypeScript 5.x** | 全栈统一 |
| 构建 | **Vite 6** | 快，生态好 |
| 样式 | **Tailwind CSS 4** | 原子化 CSS，配合设计系统 |
| 状态管理 | **Zustand** | 轻量，persist 中间件开箱即用 |
| 服务端状态 | **TanStack Query** | 缓存/重试/乐观更新 |
| 路由 | **React Router 7** | 标准选择 |
| 动效 | **Framer Motion** + **Three.js** | 星轨动效、毛玻璃、粒子系统 |
| 毛玻璃 | **BackdropFilter CSS** | 性能优于同屏 Three.js |

### 桌面壳

| 类别 | 选择 |
|------|------|
| Shell | **Electron 42+** |
| 打包 | **electron-builder**（NSIS / DMG / AppImage）|
| 更新 | **electron-updater** + GitHub Releases |
| 状态 | **electron-store** |

## 五、核心架构决策

### 5.1 Agent Loop（区别于 LeAgent 的关键）

不采用 LeAgent 的全量工具共享上下文模式，而是每个星官独立的 Loop 实例：

```
用户输入 → 紫微路由引擎（轻量模型，仅 3-5 个路由工具）
  │
  ├── 识别目标星官
  ├── 拉起该星官的 Loop（隔离的 QueryEngine）
  │     ├── 工具集：仅该星官白名单（3-8 个）
  │     ├── 历史：仅该星官的独立会话
  │     ├── 记忆：情景记忆独立，语义记忆跨星官共享
  │     └── 权限：该星官的专属 workspace
  ├── 执行工具
  └── 返回结果 → 紫微汇总 → 用户
```

### 5.2 紫微路由协议

```typescript
interface StarRouteRequest {
  source: string          // 来源星官（通常是紫微）
  target: string          // 目标星官 ID
  task: string            // 任务描述
  context_summary: string // 上下文摘要（非全量）
  message_history: Message[]  // 本轮的即时消息（非历史）
}

interface StarRouteResponse {
  source: string
  output: string
  artifacts?: Artifact[]
  memory_updates?: MemoryDelta[]
}
```

### 5.3 事件系统位置

事件引擎挂载在人格管理层，不在引擎层。这是刻意的架构选择——事件是"星官的行为"而非"工具的执行"：

```
事件引擎 ← 定时器 / 使用统计 / 系统钩子
  └─→ 触发 → 匹配星官 → 唤醒/激活 → 走标准 Loop
```

### 5.4 前端渲染管线

```
SSE / WebSocket
  └─→ ChatStore（Zustand）
       └─→ ChatView 渲染消息流
            ├── 纯文本 → MarkdownRenderer
            ├── 工具调用 → 星轨动效（Framer Motion）
            ├── 生成式 UI → 动态组件加载
            └── 事件触发 → 星官唤醒动画（Three.js 粒子）
```

## 六、与 Yi-Lin / LeAgent 的对比总结

| 维度 | Yi-Lin | LeAgent | 天枢 |
|------|--------|---------|------|
| Loop | 原型级，一次调 LLM + 串行执行 | 生产级，6 种恢复 + checkpoint | 生产级 + 星官隔离 |
| 角色 | ✅ 有 soul.md + character.json | ❌ 无角色系统 | 星官体系 + 路由 + 羁绊 |
| 工具集 | 全量塞给一个 agent | 全量塞给一个 agent | **每人 3-8 个领域工具** |
| 上下文 | 一个巨大窗口 | 一个巨大窗口 + autocompact | **每人独立窗口 + 摘要传递** |
| 内存 | 扁平 | 三区混合 | 三区 + 按星官隔离 |
| 前端 | Vue，工具式布局 | React，现代极简 | **React，国风水墨 + 动效** |
| 事件 | 简单触发器 | 规则引擎 | **六种游戏化事件** |
| 游戏化 | ❌ | ❌ | 唤醒/沉睡/羁绊/命盘/彩蛋 |
| UGC | ❌ | ❌ | 织女造星 + 创作者经济 |

## 七、MVP 范围（第一阶段）

1. **后端 Loop** — 多星官隔离的 QueryEngine + 紫微路由 + 基础 Context 压缩
2. **三个星官** — 长庚（前台）、天璇（编码）、文曲（文书），带独立工具集和记忆
3. **前端基础** — 左右布局 + 星官侧边栏 + 对话界面 + 星轨路由动效
4. **Electron 壳** — splash + 打包 + 基本 IPC
5. **数据持久化** — SQLite 会话/消息/记忆存储

不做：事件系统、羁绊、命盘、UGC 市场（第二阶段）。
